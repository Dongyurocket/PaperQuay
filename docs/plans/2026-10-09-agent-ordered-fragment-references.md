## 1. 用户目标与呈现样例

下面仅为格式示意，文献 A/B 不是实际论文，也不代表已核验结论：

> 该方法在指定工况下改善了目标指标[1]，另一工况的限制见原文讨论[2]。另一项研究给出了补充解释[3]。前述结果还表明该指标与参数变化有关[1]。
>
> **参考文献**
>
> [1] 文献 A，第 5 页，结果片段。
>
> [2] 文献 A，第 8 页，讨论片段。
>
> [3] 文献 B，第 3 页，方法片段。

本功能的编号单位是“证据片段”，不是“论文”。因此文献 A 可以出现在列表的多个条目中；每个条目对应一个独立的定位目标。同一页上的不同片段也允许不同编号。

## 2. 当前实现与差距

以下为实施前源代码基线，保留用于解释本次变更；实施后行为见第 11 节：

| 位置 | 当前行为 | 与目标的差距 |
| --- | --- | --- |
| `src/services/agentCitationRegistry.ts` | 运行内按检索发现顺序分配 `citation.label`；模型复制 `[[cite:<id>]]` | 显示编号未按正文首次引用顺序生成 |
| `src/features/agent/agentCitationRendering.ts` | 逐出现解析绑定；正文使用 citation 的原始 label；`usedVerifiedAgentCitations()` 过滤后仍保持原引用数组顺序 | 正文和文末没有统一的回答级顺序模型 |

| `src/features/agent/AgentWorkspaceMessages.tsx` | 正文后显示核验信息和“已核验证据”分组按钮 | 不符合正文后紧接有序参考文献列表的形式 |
| `src/features/agent/AgentMarkdown.tsx` | `AgentCitationMarker` 仅允许已核验的 occurrence 点击，但按钮直接读取 `citation.label` | 需要消费新的显示编号，同时保留核验门禁 |
| `src/features/agent/AgentCitationEvidence.tsx` | 明细仍显示原始 label | 会与新正文编号不一致，需要共享显示模型 |
| `src/features/agent/AgentWorkspace.tsx` | `handleOpenRagCitation()` 传递文献 ID、页码、block、预览文字；锚点标题含原 label | 定位目标可复用，但跳转标题需要与显示编号一致 |

当前 citation ID 通常由文献、来源类型及 chunk ID 组成，见 `libraryAgent.ts` 中 `agent-rag:${paper.id}:${sourceType}:${chunkId}` 的构造。现有身份足以区分同页不同 chunk；不能改为按 `paperId + pageIndex` 去重。

## 3. 编号与核验规则

1. 每条 assistant 回答单独从 `[1]` 开始；新一轮回答不继承上一轮显示编号。
2. 在原始回答上解析并核验 occurrence，再按正文偏移升序扫描。只为“来源身份唯一且该次引用已核验”的 occurrence 分配正式数字。
3. 首次遇到一个已通过核验的 `citation.id` 时分配下一个编号；后续通过核验且引用同一 ID 的 occurrence 复用该编号。
4. 不同 citation ID 保留不同条目，即使论文、页码、block 或片段文字相同。首期不引入跨 ID 的模糊去重，避免把不同解析来源或版本错误合并。
5. 同一个 ID 在不同句子中分别核验。某一句不通过时，该次出现不能因其他句已通过而变为可点击，也不能显示为正常的有效数字引用。
6. 文末只列至少有一次有效引用的片段，按分配编号排序；检索到但正文未有效引用的材料不进入正式列表。
7. 未验证或核验失败的 occurrence 显示非数字状态标记，例如“待核验”“未验证”“引用未通过”；保留具体原因的 tooltip 和明细，不占用正式编号。
8. 例如正文的来源发现顺序为 A、B、C，而有效引用顺序为 C、A、C、B，则显示 `[1] [2] [1] [3]`，列表依次为 C、A、B。
9. 若来源 A 首次出现失败、来源 B 首次出现通过、来源 A 后一次通过，则失败处保留状态标记，B 为 `[1]`，A 为 `[2]`。列表顺序以有效引用首次出现为准。
10. 重核改变核验状态后，同步重建整条消息的编号和列表；编号可能变化，但每个有效编号始终对应同一个当前展示条目。重核期间沿用现有清除旧绑定的处理，不临时保留失效的可信链接。

数字仅用于展示，证据身份与可信状态仍由原始 token、canonical citation 和逐次绑定决定。核验通过只代表现有核验机制认定该片段支撑该句，不承诺模型核验永远准确。

## 4. 统一展示模型

### 4.1 建议数据结构

在 `agentCitationRendering.ts` 内新增纯函数（建议名 `buildAgentAnswerReferences`），生成正文和文末共同消费的结果：

```ts
interface AgentAnswerReference {
  number: number;
  citationId: string;
  citation: LibraryAgentRagCitation;
  firstVerifiedOffset: number;
}

interface AgentAnswerCitationOccurrence {
  binding: AgentCitationBinding;
  citation?: LibraryAgentRagCitation;
  referenceNumber?: number; // 仅本次出现已核验时存在
}

interface AgentAnswerReferenceModel {
  occurrences: AgentAnswerCitationOccurrence[];
  references: AgentAnswerReference[];
}
```

类型为实施建议，最终命名遵循本地惯例；核心契约不得改变。

### 4.2 生成算法与消费边界

1. 复用 `resolveAgentCitationBindings()`，在原始 `message.content` 上重新检查身份与持久化绑定，保留当前对陈旧、歧义和伪造引用的拒绝。
2. 扫描解析结果，用 `Map<citationId, reference>` 保存已分配条目；每个有效 occurrence 记录其 `referenceNumber`。
3. 同一消息容器用 `useMemo` 构建一次模型，交给 `AgentMarkdown`、参考文献列表和核验明细消费。兼容其他 `AgentMarkdown` 调用者，可在未传模型时使用同一纯函数生成。
4. `injectAgentCitationBindings()` 消费 occurrence 的显示编号，保留随机链接命名空间和对模型伪造 href 的清洗；失败 occurrence 使用状态文案。
5. `AgentCitationMarker` 使用显式 `referenceNumber`，不能继续直接读取 `citation.label`；点击仍传原始 canonical citation。
6. 文末每个条目与正文复用同一 reference；明细对有效 occurrence 使用新编号，对失败 occurrence 使用位置及原因，不回退显示旧 label。

不得修改 `message.content`、canonical `citation.id/label`、`citationBindings` 的偏移、原始 token 或句子文本来完成显示重编号。否则会破坏已有核验匹配、上下文恢复和运行内注册表契约。

### 4.3 片段粒度边界

- 首期以现有 citation/chunk 为片段单位。同页不同 chunk/ID 能区分；同一 chunk 内模型引用不同子句，仍复用同一个编号。
- 若以后要求同一 chunk 内不同子段分别编号，需要真实的子段范围和独立证据身份，再扩展 token/定位数据；本计划不靠模型编造范围或按文字相似度拆分。
- 不对当前不含引用的回答自动添加来源；需要模型通过现有结构化 token 协议指出实际证据。

## 5. 正文、列表与交互

### 5.1 正文引用

- 使用紧凑的 `[n]` 文本按钮，与正文基线对齐，不把编号做成大号胶囊；点击直接打开文献定位。
- 保留键盘焦点和可访问名称，例如“引用 2：文献标题，第 8 页”。
- 悬停显示本地题名、PDF 页码和片段预览；长标题及公式预览应能换行，不能撑破消息宽度。
- 同一位置的多条来源分别显示，例如 `[1][2]`，不把多个不同定位目标压成一个按钮。

### 5.2 文末参考文献

- 用有序列表替换这条消息的 `AgentRagCitationChips`；标题为“参考文献 / References”。
- 正文后紧接该列表，核验摘要、明细和“本轮检索材料”放在其后；没有正式条目时不显示空参考文献标题，仍保留必要的核验状态。
- 条目至少包含 `[n]`、文献题名、可用的 PDF 页码和可区分片段的预览；同文献同页多条时，预览不能省略成无法区分的相同文字。
- 可从现有本地文献信息补充作者、年份、期刊和 DOI；缺失字段省略，不调用模型补造，不发起额外网络查询。
- 显示页码采用 `pageIndex + 1`，含义为 PDF 页序；没有可靠印刷页码映射时不混用印刷页码。
- 条目编号/题名作为定位入口，与正文使用同一回调和同一目标；长片段按条目提供展开控制。
- 正式列表默认按序完整呈现，不保留现有“默认六篇分组”的隐藏规则；窄窗口允许换行，不引入横向滚动或嵌套卡片。
- 大量引用情况下只渲染轻量文本和受限长度预览，不在列表内挂载 PDF 图像、全文 Markdown 或 KaTeX。

### 5.3 模型输出约束

沿用 `AGENT_CITATION_PROTOCOL`，补充“只在正文复制原始证据 token；不要生成数字编号或手写文末参考文献，列表由应用根据有效引用生成”。检查各回答路径是否注入共享协议。

模型意外手写的来源列表不得成为第二套可点击引用。程序不通过全局删除“参考文献”标题来处理，因为用户也可能要求分析参考文献章节；如确需移除模型附录，须另有明确结构协议。本期通过共享提示和统一列表先保证权威编号来源唯一，并保留对所有模型输出引用的核验门禁。

## 6. 跳转定位及降级

1. 复用 `handleOpenRagCitation()` 和 `emitJumpToNoteAnchor()`；仍使用 canonical `paperId`、`blockId`、`pageIndex`、`previewText`、`sourceType`。
2. 为跳转回调增加可选显示编号参数（或等效展示上下文），仅用于 `anchorLabel` 和界面提示；不克隆并改写 canonical label 来冒充新引用对象。所有调用方须核对，旧调用保持兼容。
3. 有可用结构块时定位相应 block，并验证现有阅读器的聚焦/高亮行为。`previewText` 仅作为定位辅助；重复文本不能当作唯一身份。
4. 无可用 block 或解析版本改变时，退回 citation 的可靠 PDF 页码，并提示“已定位到页面，原片段暂不可定位”。
5. 只有页码的 PDF 文本来源可按页打开。本次已确认入口传入的 bbox 为整页占位信息，不能宣称它支持精确片段框选；若要框选，必须有真实的 bbox 或可唯一解析的文本范围。
6. 页码缺失时只打开文献，明确提示无法定位片段；文献/PDF 不可用时显示可恢复错误，不打开另一篇论文作为替代。
7. 实施时审查阅读器对旧 block、越界页码和不存在文献的既有处理；只有确有缺口时补最小改动，并增加对应回归，不预先扩大到阅读器重构。

## 7. 流式、历史消息与持久化

- 流式生成时尚未核验的完整 token 显示“待核验”；跨 delta 的半个 token 暂不渲染为链接，也不泄露内部 ID，可复用现有解析机制并补充显示处理。
- 最终正文与核验结果到齐后一次生成正式编号。生成中断或恢复失败时，未验证片段仍不可点。
- 对持有完整 token/citation/binding 的历史消息，可以在读取时生成展示模型；禁止为渲染旧消息自动调用模型重核。
- 只有裸数字的 legacy 消息保留原文可读性，标明未验证，不按旧 label 猜测新来源；重核按钮仍遵循现有协议能力。
- 展示模型是派生数据，首期不新增 SQLite 表或持久化数字编号。原始回答、canonical citations 和 bindings 继续按已有方式保存。
- 相同消息快照在重载、切换会话和 fork 后生成相同映射；当前绑定不能因其他消息有相同 ID 而被共享放行。
- 编号稳定性以相同原始正文、引用集合和核验结果为前提。显式重核后允许重新编号，正文和列表必须同步更新。

### 9.2 桌面端验收

使用真实开发版 Electron 和本地有页码/结构块的文献；发送请求前确认当前模型为 `deepseek-flash`。

1. 多文献回答：正文首引顺序与检索顺序不同，逐个检查编号、列表和题名。
2. 同文献不同页、同页不同片段：点击每个正文编号及对应文末条目，截图记录目标题名、页码、block/片段预览；确认没有被页面分组吞掉。
3. 同片段复用：多个正文位置使用同编号，文末只有一个条目；核对每次出现的核验状态。
4. 核验失败与重试：失败处不可点；重核后变化同步到正文、列表和明细，不增加无必要的检索或核验请求。
5. 流式、中止、重新加载与会话 fork：检查待核验状态及最终一致性，历史阅读不自动触发模型调用。
6. 窄窗口和长题名：在约 1024x768 窗口及系统缩放 125%/150% 下检查换行、焦点、tooltip 和多条目列表，无内容遮挡。
7. 定位降级：分别覆盖失效 block、缺页码和 PDF 不可用，记录页面定位与片段定位的区别，不能仅凭打开文献判定精确片段定位通过。
