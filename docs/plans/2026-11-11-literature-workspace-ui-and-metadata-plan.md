## 3. 视觉与布局规范

### 3.1 学术化表达

沿用项目中性色和青绿色强调色令牌。正文与书目信息使用高可读性的文字色；强调色只用于主动作、选中态和必要提示。通过标题层级、列对齐、细分隔线组织信息，减少一项功能一个大卡片的做法。

| 项目 | 建议规格 | 使用原则 |
| --- | --- | --- |
| 正文与表单 | 13–14px | 不用缩小正文代替布局调整 |
| 文献标题 | 15–16px，适度加粗 | 原文与中文标题主次明确，不同时使用大标题 |
| 标签、说明与状态 | 12px，最低遵循系统 11px | 重要状态不只靠颜色区分 |
| 常规控件高度 | 32–36px | 按钮、输入、下拉对齐 |
| 行与分组间距 | 4px 步进，常用 8／12／16px | 保留足够点击区域与阅读间隔 |
| 圆角 | 控件使用现有 8px 令牌 | 避免大量胶囊化和圆角套圆角 |
| 阴影 | 常规内容用边框或分隔线；弹层复用系统阴影 | 内容区减少悬浮感 |

复用 `--pq-*`、`.pq-input`、`.pq-button`、`Dialog`、统一菜单、Toast 和任务中心。浅色、深色、中文、英文均纳入验收；正文对比度按现有设计系统要求验证。

### 3.2 密度与宽度

- 文献列表保持可用的最小宽度；不要求在 360px 栏宽中强行放下一整行控件。
- 根据列表或详情容器实际宽度折叠控件，避免只按浏览器视口断点判断。
- 较窄列表采用两行有序布局：第一行搜索，第二行筛选、排序、导入及更多；避免任意换行。
- 条件标签独立占一条轻量区域；较多时显示前几项与“其余 N 项”，可展开查看全部。
- 专用编辑窗口建议宽 880–1040px，受视口约束；窄窗口转为单列，内容滚动，底部动作始终可达。
- 长标题、作者、摘要可展开；完整内容也应能通过键盘访问，不能只依赖鼠标悬停。

### 3.3 助手栏“新建会话”加号主题修复

用户截图对应模型选择器右侧、历史记录与收起侧栏之间的“新建会话”按钮。浅色主题改为浅青绿底、清晰的青绿色加号和轻边框，去掉黑色实心块与重投影，使其与相邻工具协调。保留现有点击区域和布局，不通过缩小按钮或降低图标不透明度弱化视觉。

| 状态 | 目标 |
| --- | --- |
| 浅色默认 | 背景用 `--pq-accent-soft`，图标用 `--pq-accent`，边框用 `--pq-accent-border`；圆角用 `--pq-radius-sm`，默认无重投影 |
| 深色默认 | 使用同名令牌的深色值，保持深底与清晰亮图标，避免纯白实心块或照搬浅色值 |
| hover／active | 用已有强调背景与边框令牌提供可辨反馈；图标不变暗、不消失，按下不造成尺寸或位置跳动 |
| focus-visible | 复用可见焦点环；Tab 可到达，Enter／Space 仍执行新建会话；保留中英文 title 与 aria-label |
| 禁用，如有业务条件 | 仅在实际存在不可用状态时应用统一禁用样式，并禁止触发；普通运行状态不擅自增加禁用规则 |

修复应从按钮样式来源和 CSS 优先级处理：移除该按钮的硬编码调色板类和固定 RGBA 阴影，用已有组件变体或明确的语义修饰类控制底色、图标与交互状态。不得新增属性选择器补丁、大范围 `!important` 或全局改色来掩盖局部冲突。确需新增令牌时，同时定义浅色／深色值并核对受影响入口。

在浏览器或桌面实际计算样式中核对颜色与层叠；加号图标对按钮底色的非文本对比度目标不低于 3:1。截取浅色／深色以及 hover／键盘焦点对照图，覆盖助手嵌入与浮动窗口中实际复用的入口、主题即时切换及 125%／150% 缩放。同类新建会话入口仅在复用相同问题样式时同步修复，不将此项扩大成全应用按钮重设计。

本项只调整呈现与可访问性，保留 `handleCreateSessionClick` 的现有行为；新建会话、历史切换、输入草稿及运行中任务的既有规则均需回归。计划无需依赖临时截图文件在其他机器可用，实施以本节描述和源码入口为准。

## 4. 文献列表顶部与批量操作

### 4.1 工具栏信息架构

建议宽栏结构：

```text
[选择] [搜索标题、作者、摘要、DOI…             ] [筛选 3] [排序] [导入 PDF] [⋯]
结果 128 篇   年份 2020–2026 ×  类型：期刊 ×  缺少 DOI ×             清空条件
```

第二阶段增加命名视图入口。示意数量只用于解释布局。

| 入口 | 行为 |
| --- | --- |
| 搜索 | 保留当前跨字段文本搜索与防抖；支持一键清空 |
| 筛选 | 统一分组面板，显示生效条件数；条件数按维度计算 |
| 排序 | 字段与方向分离；涵盖手动、标题、作者、年份、添加、更新、最近阅读 |
| 导入 PDF | 保留文字主入口，不隐藏到多层菜单 |
| 更多 | 显示设置、刷新、存储体检等低频操作，按组分隔 |
| 显示设置 | 中英标题／中文／原文；只影响呈现，不进入筛选条件 |

搜索与当前分类共同约束结果。分类上下文明确显示；“清空条件”清除搜索和附加筛选，保留当前分类。回到全库使用独立的“所有文献”导航，避免不清楚清空后身处何处。

### 4.2 筛选交互

面板按“常用、文献属性、阅读与附件、处理状态、元数据缺项”分组。首次展示常用项，其余可展开。作者、刊物和标签使用可搜索候选，不要求滚动长下拉。

面板内编辑条件先形成临时值，点击“应用筛选”统一生效并关闭；“取消”丢弃本次修改。范围错误时就地提示。已生效条件标签可直接移除，整组变化只触发一次查询与一次清选通知。

| 分组 | 目标筛选维度 | 语义与实现注意 |
| --- | --- | --- |
| 文献属性 | 年份范围、作者、刊物／会议、文献类型、关键词 | 年份为闭区间；未知年份不计入数值范围，可单独选取 |
| 分类与标签 | 分类、包含子分类、标签 | 分类与左栏统一成同一状态；继承当前递归能力，避免双重分类上下文 |
| 管理与阅读 | 收藏／未收藏、未读／已读、导入时间、最近阅读时间 | 未读建议按无有效 `lastReadAt` 定义；阅读时间与阅读进度区别展示 |
| 阅读进度 | 进度范围 | 仅表达已有进度记录，不宣称已理解或精读；不新增学习状态推断 |
| 附件 | 有／无原文 PDF、有／无译文 PDF | 登记附件与实际文件可用性区分；文件缺失不能显示为可打开 |
| 文档处理 | 解析、全文翻译、AI 概览 | 区分未处理、运行中、已完成、失败，以及状态待核实 |
| 知识库 | 已收录／已排除；索引就绪／待处理／失败／无索引 | 成员资格与索引可用性是两种独立条件 |
| 元数据缺项 | 缺 DOI、作者、年份、刊物、摘要、关键词等 | 空串与空白视为缺失；类型不适用字段不算缺项 |

组合规则：不同维度 AND，同一维度多选 OR。例如“年份 2020–2026、类型为期刊或会议、标签为传热或流体、缺 DOI 或摘要”有明确且可见的解释；缺项组表示“任一所选字段缺失”。不在首版增加任意嵌套的布尔规则编辑器。

处理状态必须覆盖全库结果。现有前端缓存没有某篇状态时，应显示“待核实”，不能当作“未处理”。全文翻译的结构化成果与附加的译文 PDF 独立判断。

### 4.3 选择与批量工具条

点击“选择”进入明确的多选模式；复选框可见，点击文献行切换选中，不因普通点击退出。Ctrl／Cmd 与 Shift 保留为快捷方式；Shift 范围维持按当前已加载排序区间选择，并在帮助中说明。

多选时用批量工具条替换常规操作行，保留简洁的搜索上下文与条件提示：

```text
[全选匹配结果] 已选 128 篇   [移动分类] [收藏] [导出] [更多] [退出选择]
```

- 全选基于统一查询枚举全部匹配 ID，覆盖未加载页面，保存当时的 ID 快照。
- 全选开始时固定归一化查询与请求序号；枚举期间条件变化、退出选择或切换库时丢弃旧结果。排序变化保留已选 ID；枚举本身采用固定排序，避免翻页期间改序造成重漏。
- 后续导入不自动纳入已选范围；显示“已选 N 篇”，不把变化后的结果总数误称为全部已选。
- 搜索、分类或任何筛选条件生效时清空旧选择，并提供一次简短提示；排序和标题显示切换不清空。
- 全选后可取消单篇；三态复选框、已选数与实际 ID 集合一致。
- 保留移动分类、标题翻译、Bib 导出、知识库操作、收藏、删除，以及 `0.4.25` 的“设置译版语言”；第二阶段补齐取消收藏与批量标签。
- 批量动作使用同一份所选 ID 快照，不退化为只操作当前页；长任务沿用任务中心，结束后报告成功、失败和跳过数量。
- 批量补取以快照 ID 为准，不能再次用当前筛选排除已选文献。已删除或不可读取的文献列为明确的缺失／跳过项；首版提供有界分批 ID 查询，避免为少量选择反复扫描全库。
- 译版语言批量保存继续采用已有的整批事务与原值冲突检查；其他批量任务沿用各自的部分失败语义，不强行统一为单事务。
- 删除等现有确认流程继续复用统一确认组件；常规筛选与保存不增加额外确认。

### 4.4 反馈与空态

文库为空显示导入；筛选无结果显示当前条件、清空入口；查询失败显示重试并保留条件。加载中保留工具栏，不把旧请求的迟到响应覆盖当前结果。刷新保持搜索、筛选、排序和当前选中上下文，并剔除已不存在的所选 ID。

### 4.5 右键文献：打开所在位置

文献行的右键菜单新增“打开所在位置”子菜单；详情头部“更多”和“处理与附件”提供同一入口，键盘菜单键／Shift+F10 可以使用。动作在 Windows 文件资源管理器中定位文件或打开目录，文件阅读仍使用现有阅读入口。

| 菜单项 | 目标与显示规则 |
| --- | --- |
| 原文 PDF 所在位置 | 按文献登记来源解析实际原文；文件存在时打开资源管理器并选中文件 |
| 译文 PDF 所在位置 | 单份直接定位；多份按实际语言和文件名列出，不猜测用户要打开哪一份 |
| Markdown 所在位置 | 定位已关联且实际存在的 Markdown，如解析产物 `full.md`；与全文翻译 Markdown 分开标明 |
| 解析数据所在位置 | 打开实际解析目录；下级可定位已有 `content_list_v2.json`、`content_list.json`、`middle.json` 等文件 |
| 其他关联数据 | 有明确关联时列出图片、概览、翻译目录及批注 PDF；不存在的成果显示原因，不制造占位目录 |

菜单先显示“检查文件位置”，异步返回存在、缺失、未生成、外部来源无本地文件或版本未核实。右键命中的 `paperId` 是操作对象；不随详情当前选择或迟到响应变化。多选时该菜单仍只操作右键的一篇，避免批量弹出资源管理器窗口；选择集合保持原样。

位置解析复用登记附件与当前／历史缓存兼容规则。当前缓存的 `document-*` 目录和旧标题目录均需检查，不能用当前标题拼接路径就报告已找到。历史候选缺少可靠归属时显示“关联待核实”，不自动指向同名文献；多版本标明当前／历史及来源。后续 manifest 接入只扩展此解析器，图谱证据和长文档面板复用同一契约。

缺失文件保留其状态；仅当已知父目录实际存在时提供独立的“打开父目录”。点击前复核存在性，处理检查后文件被移动、删除和系统打开失败的情况。定位动作不触发解析、下载、模型调用、迁移或目录创建。

## 5. 详情侧栏

### 5.1 固定摘要头部

去掉重复的“文献详情／已选择文献”双标题。摘要头部展示主标题、次标题、作者摘要、年份与刊物，提供打开阅读、收藏、编辑和更多。

长标题先显示有限行数并提供展开；完整标题保留在资料页。作者较多时显示前若干位及“等 N 人”，可展开。头部高度应有上限，避免长标题挤占全部内容。

无可用原文 PDF 时，阅读按钮呈现“关联 PDF”等适合的下一步，并说明缺失状态。不得让一个无法打开的阅读按钮维持正常可点击外观。

### 5.2 页签与内容

| 页签 | 主要内容 | 紧凑呈现 |
| --- | --- | --- |
| 资料，默认 | 类型、年份、作者、刊物、出版字段、DOI、URL、摘要、关键词、分类、标签、个人笔记与引用 | 标签和值对齐；短字段双列，长字段通栏；长摘要与笔记可展开 |
| 处理与附件 | 原文与译文、解析、全文翻译、概览生成、知识库资格与索引 | 每个任务一行：名称、状态、主动作、更多；避免多层卡片 |
| AI 概览 | 已生成的章节与内容 | 紧凑章节导航；未生成时提供生成入口 |
| 阅读记录 | 阅读时长、最近阅读、活跃区段与图 | 图表归入此页；注明现有统计对应的附件来源 |

首次与新选中文献默认进入“资料”；正在运行的处理任务通过页签状态提示持续可见。阅读记录目前取最近更新的一份有效热图，不在此次布局调整中改称多附件累计统计。

知识库用“收录资格＋索引状态”两项表达；任务失败直接提供错误摘要与重试入口。任务仍运行时防止重复提交，缺少前置成果时解释依赖并给出入口。

附件保留打开、关联／替换／移除译文等操作，并按第 4.5 节新增“打开所在位置”。区分解除关联与删除磁盘文件的含义；不得把现有带文件删除的移除操作包装成含义模糊的无提示按钮。具体文件治理沿用资产计划。

译版行保留“设置语言”，支持设置、修改和清除；未知值显示“语言待确认”。附加译版继续确认实际语言，翻译目标语言仅作为候选值。语言更新复用专用接口与 `emitNativePaperUpdated`，不并入书目保存，不触发 PDF 重载。概览输出语言、全文翻译目标语言和附件语言分别呈现，不能共用一个隐含默认值。

### 5.3 阅读器顶栏与概览阶段

此范围包括图 1 的阅读器顶栏和图 2 的概览阶段，不重做 PDF 阅读器本身、问答面板或三种现有阅读布局。

#### 顶栏分组

| 控件 | 呈现规则 |
| --- | --- |
| 概览／阅读 | 作为稳定的阶段切换入口，一直清晰可见 |
| 单栏、双栏、PDF 对照 | 仅在阅读阶段显示；保留既有可用性和缺译文时的提示 |
| PDF 来源／版本 | 仅在阅读阶段显示，与阅读布局控件归为阅读设置组 |
| 沉浸阅读、状态栏显示等低频工具 | 收入统一的工具菜单；菜单名和图标可辨识，保留当前设置持久化 |
| 文献标题、作者、年份、当前 PDF | 作为次级上下文，窄容器下可收缩或隐藏，不挤压阶段和核心动作 |

阶段页签、阅读阶段专属布局和来源控件、工具菜单已有实现。此处验收重点是容器响应、低频动作收纳和入口连续性。原版／译版的真实来源、已知／未知语言、完整文件名提示、独立加载与错误状态继续使用现有链路。

按顶栏实际可用容器宽度折叠标签与文字，设置明确的紧凑布局；不要只依赖整窗 `2xl` 断点。隐藏低频功能不能使其不可发现，键盘焦点和无障碍名称保持完整。沉浸模式仍可隐藏顶栏，并保留返回常规阅读的可见快捷操作。

#### 概览阶段布局

- 顶部使用一行紧凑书目摘要：标题可截断并展开，作者、年份和来源为次级信息。标题不与一组固定宽度按钮抢同一行。
- 操作集中到书目摘要下方：阅读入口为主；MinerU 解析、强制重解析、翻译、刷新概览等按频率和风险分组。强制重解析继续说明会重新上传、消耗额度等影响。
- AI 概览正文成为主要内容区域；已生成时优先显示内容与章节。无概览时才显示“生成概览”主入口；生成中显示进度，失败显示原因和重试。
- PDF、JSON、解析状态等文件信息压缩为紧凑状态行或可折叠信息区。只在概览**实际剩余容器宽度**足够时使用侧栏；与助手面板同时占宽时不能仍强制保留 360px 列。
- 允许适配式侧栏，但不制造新的固定宽度下限。窄区按顺序显示“书目摘要 → 主要动作 → 概览正文 → 可展开文件状态”。
- 移除超大标题和厚重渐变卡片式层级，改用现有 `--pq-*` 令牌、正文排版、细分隔线和一致的按钮规格。不得引入绕过设计系统的硬编码调色板或阴影。

#### 已生成概览的恢复、刷新与过期状态

现状核查已确认：阅读历史和磁盘缓存存储结构化概览，原生文库 `aiSummary` 保存格式化文本。source key 考虑文献身份、提示词版本、语言、来源模式和内容／来源签名。历史恢复当前还依赖 PDF 来源就绪；磁盘缓存读取在生成函数内受模型与内容前置检查约束。普通生成函数会优先命中缓存，所以当前“刷新”文案也不保证重算。本次未运行具体文献，不能据静态路径判断某篇内容实际存于何处。

目标行为：

1. 将“加载已保存概览”做成与“生成／刷新概览”分离的读取流程。稳定文献身份就绪后先显示可关联的历史或文库文本，来源 key 就绪后补做精确缓存读取与版本校验；不等待 PDF 绘制、模型凭证或全文解析，也不发起模型请求。
2. 从现有存储迁移或关联可识别的概览；新格式记录稳定文献身份、概览正文、来源模式、内容签名、输出语言、提示版本和生成时间。保持旧缓存可读，不因新索引缺失或读取失败删除已有内容。不要为恢复单篇概览而无界扫描整个磁盘缓存目录。
3. source key 与当前来源一致时标记“与当前文档匹配”。若已保存内容能关联到同一文献但来源、语言或提示版本不一致，仍展示该版本并标记“可能需要更新”，说明可确认的差异；不可验证其新旧时明确标为“版本未核实”，不冒称过期或匹配。
4. 对用户已保存的概览保留正文。显式“刷新概览”传入强制生成意图，绕过普通缓存命中；缺少配置时就地提示并保留旧文。刷新期间继续显示旧文和更新进度；生成成功后切换展示并保存新版本。持久化失败时保留旧存储，明确提示新内容未保存并提供重试，不能把内存成功当作保存完成。
5. 初次生成时若缓存读取尚未完成，显示独立的恢复状态，不提前显示“尚未生成”；恢复完成仍无记录时再显示生成入口。模型配置缺失不得阻止缓存读取或已保存正文的查看。
6. 概览自动恢复按文献和 source key 去重；用请求序号与 tab／文献身份防止迟到的异步响应写入切换后的文献。用户切换概览与阅读阶段不清空已恢复内容。

自动生成设置继续控制“无缓存时是否自动请求模型”，不能控制缓存恢复。自动恢复和自动生成必须是两个不同阶段、不同状态和不同反馈。

恢复优先选可验证的当前版本；其次显示同一文献最近可识别的历史版本；只有文库文本时保留文本展示并标记“版本未核实”。语言或来源不同时明确展示所读版本，不将其当作当前请求的缓存命中。缺少来源信息或生成时间时不推断新旧，也不把文本硬拆成完整 `PaperSummary`。

兼容旧 key 时保留命中的原 key 与来源信息。旧 key 写入新路径不等于通过内容验证；迁移记录必须保留验证状态，避免再次打开时被误标为当前版本。现有多个存储位置之间没有跨存储事务，后续需指定一份权威版本记录，其余作为兼容镜像；不能以依次写入冒称全局原子保存。

建议将展示内容与操作状态分开：

| 状态维度 | 值与界面要求 |
| --- | --- |
| 恢复 | 未检查／检查中／完成／读取失败；未完成前不宣称“尚未生成”，失败可重试 |
| 内容 | 无内容／结构化概览／兼容文本；有内容时始终可读 |
| 来源校验 | 当前匹配／已知差异／版本未核实；保留原 key、语言及可用来源信息 |
| 生成 | 空闲／首次生成／刷新中／失败；自动生成仅在恢复确认无记录且配置可用后进入 |
| 保存 | 已保存／保存中／未保存；写入失败可重试，不清空旧记录 |

刷新启动后提高请求序号，任何更早的恢复结果不得覆盖新内容。解析内容或来源切换引起 key 改变时重新校验；只修改书目或译版语言不能被当作 PDF 内容变化，也不自动重新生成概览。

## 6. 专用元数据编辑窗口

### 6.1 结构与字段

```text
编辑元数据                         [获取候选] [从 PDF 提取] [关闭]
基本信息  出版信息  摘要与关键词  个人整理             未保存
────────────────────────────────────────────────────────────
分组表单；长字段通栏；按类型展示出版字段
有候选时展开“当前草稿／候选／来源／采纳”比较区
────────────────────────────────────────────────────────────
字段校验与保存反馈                          [取消] [保存修改]
```

分组导航滚动定位到同一份表单，切换分组不丢失输入。补全工具用于当前文献草稿；现有右键“解析元数据”改为进入同一个核对流程，避免普通单篇入口继续绕过草稿直接落库。

| 分组 | 字段与操作 |
| --- | --- |
| 基本信息 | 原文标题、中文标题、类型、有序作者条目、年份、DOI、URL；中文标题翻译使用当前草稿标题 |
| 出版信息 | 刊物／会议／书名等载体、出版者、机构、卷、期、页码、报告号、ISBN、ISSN，按类型排列 |
| 摘要与关键词 | 多行摘要、有序或去重关键词条目；长文本可展开编辑 |
| 个人整理 | 分类、标签、个人笔记、已有引用文本；分类支持现有多分类语义 |

作者按条目维护，可添加、删除和调整顺序；姓名中的逗号不作为无条件拆分符。粘贴多作者时先预览拆分结果，再确认条目，保留中文姓名及机构作者文本。

出版者与机构独立编辑和保存，不因切换类型将同一值写入两个字段。已存在但当前类型不常用的字段保留在“其他字段”，不自动清空。

### 6.2 文献类型适配

| 类型 | 优先展示的出版字段 |
| --- | --- |
| 期刊论文 | 期刊、卷、期、页码、ISSN、出版者 |
| 会议论文 | 会议／论文集、页码、出版者、ISBN／ISSN |
| 图书 | 书名对应标题、出版者、年份、ISBN |
| 图书章节 | 章节标题、载体书名、页码、出版者、ISBN |
| 学位论文 | 授予机构、年份；其他已有字段可展开 |
| 报告 | 机构、报告号、出版者、年份 |
| 预印本 | 平台／载体、年份、DOI／URL |
| 其他或未知类型 | 通用字段与全部已有值；未知类型值保留 |

本轮优先使用已有数据模型。版次、学位级别等尚无完整结构的字段不伪装为已有能力；若后续新增，需单独补充存储与导入导出契约。

### 6.3 元数据获取与核对

1. 用户从当前草稿 DOI、标题或本地 PDF 发起获取，当前已输入内容保留。
2. 复用 OpenAlex、Crossref 检索与 PDF 首页／内嵌信息提取；新增候选查询契约，展示多个可用候选及来源。候选标题、作者、年份应足以帮助判断是否同一篇文献；现有返回单个合并对象的接口不能直接充当多候选接口。
3. DOI 未命中时可使用草稿标题重试，并说明当前查询依据。标题检索结果不能未经核对自动取首条覆盖。
4. 选择候选后展示逐字段差异；当前值来自最新草稿，不仅是已保存值。
5. 默认只勾选空缺字段；非空冲突、字段清空、作者列表替换均需用户明确采纳。支持“仅补空缺”和逐字段选择。
6. “应用到草稿”只改变草稿；底部保存成功后才写入文献。允许撤销最近一次候选应用，恢复应用前的草稿值。
7. 网络失败、无匹配或 PDF 无法提取时保留草稿并允许继续手工编辑。现有提取没有 OCR，不承诺扫描件均能识别。

候选来源与可核实的信息分开展示。若展示匹配程度，应来自实际算法并说明依据，不使用虚构置信度。LLM 辅助只复用已配置的可用能力，由用户主动触发，不能把模型推断标成出版机构确认的数据。

候选契约至少记录候选 ID、提供方、查询 DOI／标题、返回字段、字段来源及提供方结果状态（成功／无匹配／失败）。DOI 精确匹配和标题相似匹配分别呈现；合并两个提供方结果前先核对同篇身份，不能把不同文献字段拼成一个候选。远程映射补充卷、期、页码、ISSN 等实际可提供的字段；未提供的字段保持缺失。普通查询失败与部分提供方失败分别反馈，用户可继续使用其他候选。

PDF 提取独立调用现有本地预览能力；当前请求中的 `path` 不能替代本地提取。中文 LLM 兜底在新编辑器中改为明确的“智能提取”动作，展示所用模型与首页文本来源，返回值进入同一差异区。导入、全库补全的既有自动兜底先保持兼容，并记录与单篇主动触发的差异。

导入、全库补全和 Agent 流程已有不同覆盖策略。本次先统一普通单篇编辑入口与可复用的字段比较规则，避免为侧栏改造同时重写全部后台流程；其他入口的策略差异应记录并另行对齐。

### 6.4 草稿、保存与异步约束

- 草稿绑定文献 ID、打开时基线及已修改字段；输入时计算 dirty 状态。
- 保存等待异步结果；容器回调返回成功数据或抛出错误，不能在父层吞掉失败后让表单自行关闭。成功后关闭，失败保留草稿、候选与当前位置，显示可重试原因。
- 只提交发生变化的字段；`undefined` 表示不更新，允许清空的字段使用接口约定的 `null` 或空数组。
- 取消、关闭、Esc 和切换文献遵循同一规则：无修改直接退出，有修改提供“保存后离开／放弃修改／继续编辑”。
- 提交过程中防止重复保存；非必要不冻结全文献库操作。
- 检索、PDF 提取、标题翻译绑定文献 ID 与请求序号；过期结果不写入别篇文献或覆盖之后的手动输入。
- 同一文献后台更新时，无冲突字段可刷新；已修改且发生冲突的字段提示核对，不能静默重置草稿。
- 写入前在后端事务内比较待改字段的基线，避免只靠前端刷新检测并发。建议增加兼容的预期字段值契约；无关字段变化允许合并，目标字段冲突拒绝本次保存并返回最新值。现有 `library_update_paper` 尚无该能力；仅发送差异字段不能解决同字段覆盖。
- 保存成功后复用 `emitNativePaperUpdated` 同步已打开阅读器的书目信息。若写库成功但列表刷新失败，提示“已保存，列表刷新失败”并保留成功结果，避免让用户误以为需要再次写入。
- 保存后尽量保持列表滚动、当前文献与选择上下文。若修改后不再匹配当前条件，提示“该文献已不符合当前筛选”，从结果移除并按相邻位置合理选中；候选操作不改变列表。
- 表单支持 DOI／URL 的规范化与可解释校验；标题空缺禁止提交，其他缺失元数据不阻止保存。年份保留已有文本兼容，无法解析为年份的历史值不直接破坏性改写。

`UpdatePaperRequest` 已支持大部分书目字段，但不含分类变更。个人整理中的多分类保存需要显式协调已有分类服务；如与书目使用不同命令，逐项反馈并保留未成功的草稿，不能在部分成功时关闭窗口。书目修改沿用稳定文献与附件身份，不通过重建附件实现保存；数组清空提交 `[]`，并针对后端当前语义核验，不能笼统依赖类型允许的 `null`。

## 7. 查询、状态与组件设计

### 7.1 统一查询契约

在 `ListPapersRequest` 基础上扩展结构化过滤，不以修改搜索字符串来模拟全部条件。建议集中定义 `LiteratureFilterState`，并归一化为可序列化查询值；保持旧请求缺省行为兼容。

列表、总数、分页追加、全选 ID、批量数据补取使用同一归一化条件。参数绑定查询，排序保留稳定 ID 兜底；条件变化重置页码并丢弃旧查询响应。

这里的“同一条件”用于确定候选与选择范围；已捕获选择后，批量补取以快照 ID 取数，不重新按变动后的属性过滤。将归一化查询集中到同一构造器，替换当前刷新、追加、全选、保存后刷新和批量补取中分散拼接的参数。审查回调依赖，避免知识库筛选等新状态在异步闭包中使用旧值。

需要特别处理的事实与约束：

- 标签当前记录与文献关联，不能假定全库同名标签共享同一 `tagId`；多标签过滤以规范化名称或明确的全局标识匹配，避免只匹配一个文献私有标签 ID。
- 年份当前为字符串；增加可查询的年份归一化策略，保留原始值，并给未知年份明确入口。
- 原文、译文使用登记的附件角色与路径解析，不以文件名猜测译文是否存在。
- 缺项判断按类型声明适用性，例如无 DOI 不自动等同于图书信息不完整。
- 分面候选来自全库或当前范围的查询结果，不只扫描当前加载的 500 篇；首版不必给每个选项实时计算数量。
- 过滤输入先验证再生成参数化 SQL；未知枚举、无效范围不得静默变成“全部”。新契约应同步桌面服务、IPC、实际共用查询的 MCP 入口及演示数据语义。

按数据来源分两批交付，完整筛选仍属于第一阶段：

| 批次 | 维度 | 依赖与上线条件 |
| --- | --- | --- |
| A：已有持久化属性 | 年份／未知年份、作者、载体、类型、关键词、分类与多标签、收藏、阅读时间／进度、登记附件角色、知识库成员、类型适用缺项 | 扩展共享 SQL、规范化字段与分面查询；查询／计数／分页／全选全部使用同一规则后开放 |
| B：成果与可用状态 | 实际文件可用性、解析、结构化翻译、概览、RAG 索引就绪／待处理／失败 | 完成全库状态投影、回填与失效策略后开放；在此之前不提供只对当前页生效的同名筛选 |

筛选 A 可形成可验收的中间交付，但不能标记为 Q4 完成。未知状态是有效结果，不等同未处理；第一阶段完整验收必须包含 B。

### 7.2 全库处理状态

现有解析和部分任务状态来自前端计算；RAG 状态另有聚合。实施时为统一查询建立可重建的状态投影，接收已有处理完成、失败、删除和附件更新事件，避免查询时为每篇文献临时扫描磁盘。

成员资格继续以文库字段为准，RAG 可用状态以既有索引聚合服务为准，投影保留来源与更新时间。不能把文库投影变成第二套向量库。

初次补齐旧文献状态时显示进度及待核实数量；任务成功后同步结果与计数。若服务不可用、状态过期或成果路径失效，显示可解释状态并提供刷新，不把它们一律归为未处理。

| 状态来源 | 既有依据 | 投影与失效规则 |
| --- | --- | --- |
| 原文／译版 | 登记附件角色、路径与 `missing` 信息；按需体检结果 | 登记存在与文件可打开分开；附加／替换／移除／重新定位后失效，文件可用性保留检查时间 |
| MinerU 解析 | 既有解析任务、manifest 和结构化成果检测 | 绑定文献与实际来源；无检测结果记待核实，检测在后台有界执行 |
| 结构化全文翻译 | 翻译任务与已保存翻译成果 | 独立于译版 PDF；取消、失败、来源变更后重新评估可用性 |
| AI 概览 | 结构化缓存／历史与文库文本 | “有内容”和“与当前来源匹配”分开；不因文本存在就标当前版本 |
| RAG 索引 | 既有成员字段与索引聚合服务 | 成员与可用性独立；排除、重建、删除和服务失败后更新，索引内容仍由原服务管理 |

新投影只保存查询所需状态、来源身份和更新时间，不复制全文或向量。设计时明确持久化位置、版本、重建入口与事件去重；启动恢复尚未完成的任务时先复核，不能把上次“运行中”永久保留。跨文件／跨数据库状态不声称单事务一致，采用可重放事件或定期对账收敛；更新列表计数时使用同一投影版本。

### 7.3 建议的职责拆分

| 职责 | 建议模块，名称为拟议 | 复用基础 |
| --- | --- | --- |
| 查找与列表控制 | `LiteratureToolbar`、`LiteratureFilterPanel`、`ActiveFilterBar` | 现有 PaperList 和查询服务 |
| 批量选择 | `LiteratureSelectionToolbar`，独立选择状态逻辑 | `paperSelection.ts` 与全选 ID 链路 |
| 详情组织 | `PaperDetailsHeader` 与四个详情内容区 | 现有标题、附件、概览、热图逻辑 |
| 编辑 | `PaperMetadataEditorDialog`、类型字段配置 | 统一 `Dialog`、现有更新请求 |
| 候选比较 | `MetadataCandidateReview` 与字段差异工具 | 现有元数据服务和 Agent 变更预览模式 |
| 过滤状态 | 归一化过滤、查询序列化、状态投影适配 | 共享 SQL filter 与状态服务 |
| 概览生命周期 | 拟议的独立恢复／刷新状态逻辑与来源记录 | `documentReaderCache`、统一 source key、历史、文库预览；阅读器与详情复用 |
| 译版语言入口 | 现有单项／批量弹窗与专用服务 | `updateTranslatedPdfLanguages`、`emitNativePaperUpdated`；保留已有事务语义 |
| 文件位置 | 拟议 `literatureFileLocations` 服务与右键菜单适配 | 登记附件、缓存兼容路径；图谱和长文档复用，不各自拼接路径 |

业务请求和状态协调留在清晰的容器／服务层，展示组件接收显式数据与动作。避免继续把所有表单、检索、弹窗、多选状态堆入 `LiteratureLibraryView.tsx`。

### 7.4 第一阶段必须补齐的接口契约

| 契约 | 当前缺口 | 交付要求 |
| --- | --- | --- |
| 结构化过滤与分面 | 仅有简单查询字段 | 明确枚举、空值、OR／AND、年份及类型适用性；列表／COUNT／ID 查询共用 |
| 批量按 ID 读取 | 现有前端依当前条件翻页补取 | 有界分批、保持输入 ID 顺序、返回缺失 ID；不改变冻结选择范围 |
| 元数据候选 | 单个合并对象或 `null` | 多候选、逐字段来源、提供方独立结果；旧接口与导入／Agent 兼容 |
| 书目保存与并发 | 普通更新无基线冲突检查，表单回调无可判定成功结果 | 差异提交、事务内预期字段校验、明确冲突返回、写入成功与刷新失败分开 |
| 概览恢复与刷新 | 生成函数兼做缓存读取，刷新未绕过缓存 | 只读恢复、强制刷新意图、版本验证信息、权威持久化记录与兼容镜像策略 |
| 文件位置查询与执行 | 无通用文献定位契约 | 拟议 `list_literature_file_locations(paperId, sourceVersionId?)` 返回稳定 location ID、角色、文件名、类型、版本和可用状态；`reveal_literature_file_location(paperId, locationId)` 在主进程重新解析、校验后执行 |

新增命令补齐命令注册、允许列表、前后端类型和错误映射。保存链路避免沿用会全量重建关联的通用操作来更新无关字段；验证新旧客户端缺省请求仍可工作。

位置服务以 `paperId + attachmentId + contentHash` 为来源基础，兼容可选 `assetId`；缓存产物另带角色和版本。主进程从已登记来源和配置缓存根解析目标，不接受渲染器传入任意命令或任意打开路径。文件用 `shell.showItemInFolder`，目录用 `shell.openPath` 并处理错误；存在性检查有界且不读取整份 PDF／大 JSON。该动作属于桌面 UI，不因共享查询服务就自动开放为 Agent／MCP 的系统窗口操作。

## 11. 需重点控制的实现风险

| 风险 | 处理方式 |
| --- | --- |
| 状态只覆盖已加载文献，筛选漏结果 | 全库可查询状态投影；未知状态显式呈现；列表与全选共用同一规则 |
| 筛选增加后查询变慢 | 优先 SQL 下推与适当索引；避免每次按文献扫描磁盘；实施时用代表性库规模记录耗时 |
| 异步全选回写旧条件，按当前筛选补取漏掉已选文献 | 查询指纹与请求序号保护枚举；按快照 ID 分批读取，缺失项显式报告 |
| 单篇补全复用时沿用直接写库 | 检索返回候选，比较后只改草稿；由同一保存入口写入 |
| 不同提供方候选被混合，服务失败伪装为无匹配 | 候选保留同篇依据、字段来源与提供方状态；旧单结果接口保持兼容 |
| 不同编辑入口与外部更新互相覆盖 | 差异提交、草稿基线校验、请求归属检查，冲突就地核对 |
| 保存失败被父层吞掉，或写库成功后刷新失败被当成写入失败 | 表单等待明确结果；分别反馈写入与界面刷新，保留未成功部分草稿 |
| 元数据编辑影响附件路径和缓存 | 以稳定文献／附件身份保持关联；字段改动不隐式重命名物理文件 |
| 历史概览 key 与当前 source key 不同，自动恢复误报匹配或覆盖新内容 | 保存生成来源元数据；能验证时标记当前／待更新；不可判定时标“版本未核实”；刷新成功后才替换旧文 |
| 概览恢复与自动生成耦合，读缓存可能触发模型配置检查或生成副作用 | 将只读恢复独立成生命周期；恢复不需要凭证、不更新任务状态、不调用模型；刷新才走生成链路 |
| 刷新再次命中缓存，或多位置写入失败却宣称保存成功 | 强制刷新绕过缓存；指定权威版本记录，显示持久化状态并可重试兼容镜像 |
| 文献切换时概览缓存读取迟到，覆盖当前文献内容 | 请求同时绑定文献 ID、tab ID、source key 和请求序号；提交结果前校验仍匹配 |
| 阅读器主体可用宽度受可调助手栏影响 | 用概览容器实际尺寸响应；展示与折叠状态按容器计算，不把窗口断点当内容宽度 |
| 紧凑化降低可读性与可操作性 | 保留字号、焦点与点击区域；按容器折叠，不无限缩小 |
| 复用旧元数据检索导致误匹配 | DOI 与标题重试可见；候选充分展示书目信息；冲突由用户采纳 |
| UI 重组造成已交付译版语言与对照能力回退 | 入口迁移表覆盖单项／批量／两个附加入口；继承来源身份、PDF 生命周期、分栏适配与同步回归 |
| 右键对象错位或按标题猜路径误开其他文献 | 固定右键 ID 与请求序号；来源和角色解析统一，点击时再次校验；历史归属不明时提示核实 |
| 图标通用类与局部调色板互相覆盖，修复浅色后深色回退 | 定义清晰的语义按钮变体，核对 computed style；双主题和交互状态截图，不全局覆盖工具按钮颜色 |

本方案的完成标志是文献管理与阅读形成一致的“查找 → 选择 → 核对 → 编辑／处理／阅读 → 返回结果”流程；筛选、全选范围、编辑草稿与概览恢复在真实数据下保持一致，已生成概览无需由生成按钮触发加载。
