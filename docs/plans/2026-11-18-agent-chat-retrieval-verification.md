## 跨文献向量检索性能

在仓库临时目录中新建合成 RAG 库，使用桌面 `retrieveDocumentChunks`，每个文献一个 ready 的 `pdf-text` 来源，1000 篇、每篇 10 个分块、同一模型，`topK=8`，不包含 embedding 网络请求。32 维向量连续六次耗时 152、149、147、145、151、147 ms；1536 维连续六次耗时 4372、4403、4764、4511、4363、4388 ms。这是单机单次合成数据测量，不是用户文库或 MCP 端到端基准。较高维度下的延迟明显，逐来源 KNN 在较大文库有性能风险，尚未完成优化或更大规模验证。

同一 1536 维合成库的只读 SQL 对照中，直接进行全局 KNN、召回 16 个分块并连接状态表，三次耗时 3480、3409、3379 ms；使用符合模型和 ready 状态的分块 rowid 子查询约束 KNN，三次耗时 3362、3375、3563 ms。该对照没有实现完整的 scope、排除和融合逻辑，仅表明这台机器上的向量扫描本身占用了大部分时间，不能据此断言逐来源循环是唯一瓶颈，也不能把这两条 SQL 直接替换生产检索。
