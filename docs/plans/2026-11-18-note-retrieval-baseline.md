# 笔记检索隔离基准

运行：`node --test tests/noteRetrievalBenchmark.test.mjs`。测试在临时目录创建八条合成笔记和独立 RAG 索引，不读取或上传用户数据。28 条查询及其人工相关标注位于测试文件，覆盖中英文、短语、缩写、页码、pageKind、文献和笔记 ID 范围；其中 26 条各标注一条相关笔记，另有两条无相关笔记。

向量由手写主题词规则生成，使用真实笔记向量存储和混合 RRF 路径，但不是实际 embedding 模型；部分查询与模拟向量词表共享词汇，不能将结果推广为真实语义检索质量。每条正例只有一项相关标注，故此处 hit@5 与 macro recall@5 相同。

| 路径 | hit@5 / recall@5 | 零结果数 |
| --- | --- | --- |
| 关键词 | 22/26（84.6%） | 6/28 |
| 混合 | 26/26（100%） | 1/28 |

两条负例中，混合检索对限定到无关笔记的查询返回了一条范围内但不相关的结果；被排除的目标笔记没有泄漏。该现象反映模拟向量下的候选相关性不足，不足以据此调整真实模型阈值。索引缺失和模拟 embedding 失败均验证回退到关键词并携带警告；相同输入两次运行的排序一致。

## 真实模型补充基准

使用 `Xenova/paraphrase-multilingual-MiniLM-L12-v2` 的量化 ONNX 模型（revision `2c4055b12046f11709e9df2c122e59ffbdc2f900`），CPU 推理、attention-mask mean pooling 和 L2 归一化。使用同一组隔离合成笔记和查询，未读取或上传用户文库。两次运行的排序一致：关键词 hit@5 / recall@5 为 22/26（84.6%），混合为 26/26（100%）；零结果分别为 6/28 和 1/28。两条负例中，有一条返回了范围内但不相关的笔记。每条正例仅标注一项，hit 和 recall 因此相同；样本很小且每条内容混合中英文关键词，不能据此推断真实文库质量或调整阈值。

设置 `PAPERQUAY_BENCHMARK_MODEL_DIR` 指向含 `tokenizer.json` 和 `onnx/model_quantized.onnx` 的模型目录后运行上面的测试；Python 环境需要 `numpy`、`onnxruntime` 和 `tokenizers`。不设置该变量时真实模型测试会跳过，常规测试无需下载模型。模型推理脚本只接收测试构造的字符串。

文献级 RAG exclusion 的 MCP 隔离回归见验收记录；更丰富的多相关项标注仍有助于衡量实际质量，本表不能视为真实用户库的质量评估。
