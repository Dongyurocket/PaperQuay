### 1.2 已复现与已确认的代码事实

以下为 2026-10-09 制定计划时的修改前证据，保留根因与截图判断边界；实施后的行为及验收在第 4–6、8 节和综合变更记录中说明。

1. **数值范围误解析已复现。** 使用当前 `AgentMarkdown` 的实际 React 服务端渲染，输入“飞行距离 15~30 km，平均 5 km。半径 50~200 km。”，产生一个 `<del>`，可见文本中的范围符号消失。独立解析对照设置 `remarkGfm` 的 `singleTilde: false` 后不再产生删除线。截图精确原始文本尚未取得，复现证明机制成立，不证明截图全部数值错误均由此产生。
2. **公式内引用泄漏已复现。** `$U_j$ [[cite:e]]` 正常产生引用按钮；`$U_j [[cite:e]]$` 不产生按钮，显示带随机 `#agent-binding-...` 的文本。两次均提供同一个可解析的 canonical 来源。当前只对公式中的 paper/category ID 做脱离处理，未覆盖 citation token。
3. **检索范围与注册范围不一致已确认。** `rag_search` 省略 `paperIds` 时向 `searchRag` 传入 `undefined`；底层按全库检索。返回 chunks 会生成 token，但注册循环跳过不在本轮 `papers` 中的文献。模型能收到未注册 token。此路径是 S1 的候选原因，实际运行是否走到该路径仍待核对。
4. **跨轮流式累加已确认。** 每轮 `answer_delta` 都进入同一个 `streamedAnswer`；没有轮次隔离。最终成功分支会用 `result.answer` 替换显示内容，不能把流式期间混排直接认定为最终持久化污染。
5. **限制与截断已确认。** 普通 ReAct 最多 8 轮；初始 payload 最多 20 篇、48,000 字符；`request_paper_context` 每次最多 5 篇；`rag_search` 每次 topK 为 12。工具结果超过 4,000 字符时直接切字符串，可能切断 JSON、token 或证据。上述限制属于不同层次，不能把“初始 20 篇”解读成整个运行最多可访问 20 篇。
6. **轨迹存在双重最终节点及预置时长。** 通用 `final` 与 `react-final` 并存；初始步骤有固定 120/180 ms。部分成功状态只表示轮次或工具完成，不表示证据正确或用户目标满足。
7. **0.4.8 已分离来源与内容判断。** 正常生成使用 `bindAgentCitationSources`，主动“检查内容”才执行语义检查。来源可用不等同于内容检查通过。本计划不恢复旧版“语义失败即不能查看来源”的规则。

## 2. 问题、根因与解决方向

| 问题 | 原因 | 解决方向 | 优先级 |
| --- | --- | --- | --- |
| 范围外检索及未注册 token | 工具默认全库，运行候选及注册范围更窄，范围契约分散 | 集中解析有效范围；先过滤和注册来源，再序列化模型可见证据 | P0 |
| 数值范围变删除线 | `remark-gfm` 默认允许单波浪号删除线 | 禁止单波浪号删除线，保留显式 `~~删除~~`；验证负数、小数、单位和公式 | P0 |
| 公式引用泄漏 | 先把 token 拼成 Markdown 链接，再进入数学解析 | 用 Markdown AST 消费引用节点；数学语境中的引用独立渲染，保留定位契约 | P0 |
| 流式过程与正文混排 | 所有轮次文本共用一个累加缓冲，缺少阶段与轮次身份 | 按轮次维护草稿，把工具前说明归入进度，最终正文消费最终轮结果 | P1 |
| 长工具结果损坏 | 对 JSON/正文统一字符串截断，没有结构与续取契约 | 按完整记录和段落预算序列化；明确遗漏量，支持分页或继续获取 | P1 |
| 完成状态误导 | 通用模板、轮次完成与任务完成混用，部分时间为预置值 | 单一最终节点；按真实事件收敛，区分达到预算、取消、失败和完成 | P1 |
| 完整调研缺少覆盖证据 | 通用 ReAct 预算有限，没有逐文献、逐主题覆盖台账 | 复用现有综述能力分批研究，保存覆盖、失败和未完成项 | P2 |
| 完整版退化为大纲或原则 | 未把用户交付要求转成可检查的章节和输出结构 | 建立写作与工程问答的完成标准，保留事实不足时的条件化回答 | P2 |
| 证据外推与强空白判断 | 正文自由生成，来源身份不验证语义，检索缺失被用于领域判断 | 主动内容检查按主张评估；用限定表述、反例检索与缺口记录约束论断 | P2 |

## 3. 不变量与实施边界

1. 本地来源身份继续决定可查看性；内容检查独立呈现。正常回答不新增默认逐句模型核验，也不因检查失败隐藏有效来源。
2. 保留本轮精确 `[[cite:<id>]]`、正文首次引用编号、片段级参考文献和 canonical paper/page/block 回调；模型不能自造编号、元数据或位置。
3. 笔记写入继续走既有审批及独立证据门禁；“来源可用”或“检查内容”不能授权笔记写入。
4. 回答、原始 token、引用出现位置与核验结果之间保持一致。仅展示层的数学/引用处理不得改变已保存正文偏移、绕过未知/歧义来源拒绝或允许伪造链接。
5. 用户选定范围默认约束正文检索和证据。显式要求全库可使用全库；需扩大范围时通过现有选择流程说明扩大范围。图谱可返回关联候选，但关联关系不自动成为正文证据或扩大正文检索范围。
6. 不改变用户 PDF、解析源数据、笔记、SQLite 内容与个人脚本；复现 fixture 使用隔离临时文库。真实验收仅执行用户授权的只读检索与问答。
7. 兼容旧消息及恢复 checkpoint；缺少新字段时显示未知或未记录，不能把历史候选数补成已读数。
8. 新状态仅在跨轮、恢复或 UI 消费确有需要时增加；优先扩展现有能力 artifacts、运行事件和消息契约，避免另建平行 Agent 框架。

## 4. 工作包

### W1. 统一范围与证据注册（P0）

状态：**完成**。新增 `agentPaperScope.ts` 统一 UI/服务有效范围，校验后注册再序列化；单篇真实问答及范围/registry 回归通过。

涉及：`AgentWorkspace.tsx`、`agentPaperScopes.ts`、`agentTools.ts`、`libraryAgent.ts`、`agentCitationRegistry.ts`。

1. 梳理本轮显式选择、分类、全库、对话历史候选的优先级。把“当前允许检索的文献”与“历史关联候选”分开，后者不能无条件并入硬范围。
2. 在服务层解析唯一有效检索范围，复用到 `rag_search`、`request_paper_context`、相关能力检索和来源注册；工具省略 ID 时使用有效范围。
3. 模型传入范围外 ID 时返回结构化范围错误；不得自动改成全库。允许范围为空时显式返回无可用候选，避免空数组被下层误解释为全库。
4. 检索层传入 documentKeys；结果层再次校验文献身份与范围。过期索引、删除文献或缺失本地记录返回可解释的丢弃原因。
5. 按“校验 -> 注册 -> 序列化”生成 chunks。只有成功注册的 canonical citation 才向模型提供 evidenceToken；不能给模型一条前端无法解析的引用。
6. 已授权全库时使用相应的本地文献记录补齐题名；单篇范围不能通过补齐元数据变相扩库。模型提示、工具结果和 UI 范围提示保持一致。

验收：选择 A，库中还有 B，省略 ID 的 RAG 仅查 A；显式全库可查 A/B；超范围 ID、空范围和删除后的旧索引有明确结果；每个返回 token 均在本轮 registry 中唯一解析。

### W2. 数值与数学引用渲染（P0）

状态：**完成**。实际 AST 渲染保持原始偏移/canonical；Agent、阅读助手、结构块及单块修复预览四个 Markdown 入口禁用单波浪号删除线，实际组件与桌面数值抽查通过。

涉及：`AgentMarkdown.tsx`、`agentCitationRendering.ts`、现有 Markdown 工具与组件测试。

1. 将 Agent 的 GFM 配置改为 `singleTilde: false`，保留双波浪号删除语法。先核对其他 Markdown 消费点，按实际影响扩展，不无理由改动所有阅读器。
2. 复用现有 occurrence/reference model，在 Markdown AST 层消费 citation token，避免把内部跳转字符串交给数学解析器。
3. 普通段落、行内公式和块公式分别明确处理；公式内 token 从公式表达式中取出，在相邻位置显示引用按钮，不能改写公式变量或重新猜测来源。
4. 原始消息内容保留，渲染节点记录原 occurrence 身份。代码块、代码行、未知/重复/歧义 token、流式未闭合 token 继续遵循现有边界。
5. 保留既有伪造链接防护；正文不得显示应用生成的随机内部地址。历史已存的合法 token 同样经过新渲染逻辑。

验收：`15~30`、`50~200`、`0~25`、小数与负数范围完整显示；`~~删除~~` 仍有效；公式内外引用都传相同 canonical 对象，正文编号与文末一致；公式、代码及流式半 token 不泄漏内部地址。

### W3. 流式输出与执行终态（P1）

状态：**完成**。turn 草稿、重试、缓冲关闭及代际检查已接入；单一最终节点使用实测耗时，取消/继续与会话切换桌面通过，length/异常由回归验证。恢复聊天过滤工具前草稿及空正文，底层 checkpoint 保持完整，实际循环中断后续跑回归通过。

涉及：`agentLoop.ts`、`libraryAgent.ts`、`AgentWorkspace.tsx`、`AgentWorkspace.model.ts`、运行恢复及轨迹组件。

1. 给文本事件提供 turn 身份与可判定的阶段；轮次开始清理或切换本轮草稿，不能跨轮拼接 Markdown。
2. 工具调用是否存在通常到该轮响应结束才确定。流式过程中只能把本轮文本标成临时草稿；结束后将带工具调用的文本归为进度，将无工具调用的最终轮提交为正文。
3. 过程信息通过已有状态栏/轨迹表达；最终正文不得包含未经用户请求的 token 协议、系统工作流说明和跨轮“再补一批”。优先修正数据通道，再调整提示词，不能只用正则删除开头段落。
4. 合并通用 `final` 与 `react-final` 的终态语义；“调用成功”“结果为空”“达到预算”和“任务完成”分别表达。只把真实运行时间显示为耗时，预置 120/180 ms 不再作为测量值。
5. 将 finish_reason=length、工具错误、取消、恢复和预算耗尽纳入最终事件；非空但被长度截断的回答也不能静默认定完整。
6. 保留现有最终结果覆盖流式缓存、finally 不再写回缓存以及旧 controller 不清除新运行状态的防竞态措施。

验收：连续多轮工具前说明不会拼进最终正文；最终节点只有一个；切换会话、取消、恢复、异常及非空截断均收敛准确，历史恢复不把草稿当完成回答。

3. 建立最小覆盖台账：候选文献、摘要已看、正文已检索、重点正文已读、实际引用、无关、未解析、失败、待处理；另记录子问题覆盖和证据缺口。切片命中不等于全文已读。
4. 针对“全查”明确执行口径：每篇候选都记录筛选/检索状态，相关重点文献进一步阅读；若用户要求每篇正文检查，逐篇安排并记录无法完成项。完成标准不能事后缩小。
5. 覆盖率、预算和停止条件共同决定收敛；到达时间/token/轮次预算时标记部分完成，提供已完成部分、待办及继续入口。记录真实用量，不根据回答长短推测成本。
6. 跨批次去重保存证据；任务恢复沿用原范围和台账。新摘要不得丢失关键 token，候选范围变更应单独记录。

验收：176 篇是候选数，不自动变成已读数；批次处理中断后可续；空命中、未解析及请求失败分别记录；每个子问题的证据覆盖可追踪。真实运行规模根据用户文库与实际预算确定，隔离批次测试不能冒充 176 篇真实验收。

### W6. 交付标准与证据边界（P2）

状态：**完成**。`agentDeliveryQuality.ts` 检查章节和任务结构，支持无空格编号要求及历史续写；主动内容核验拆分复合主张并优先高风险项，保持原始位置，预算外/非法响应为未知。来源导航及笔记审批独立。

涉及：现有回答提示、综述 report 阶段、`agentAnswerEvidence.ts`、`agentCitationAudit.ts` 和消息质量状态。

1. 写作任务从本轮及必要历史提取章节范围、体裁和完整度要求。交付正式段落，核对遗漏章节、未闭合内容和占位编号；`1.x` 若为用户指定编号不应擅自替换，否则标明待定或按已知结构生成。
2. 用户已要求完整版时，不以“可以再扩写”为完成依据；因证据或预算不足只能交付部分时明确说明。质量判定作为可解释检查，不能靠字数阈值宣称学术质量达标。
3. 工程问答采用任务适配结构：边界位置、类型、变量/单位、已知值与未知值、适用前提、证据及验证项。热喷流至少区分可压缩性、亚/超音速、能量方程、入口速度或总量条件、远场/出口、壁面与声学设置，不把不同适用条件合并成万能参数表。
4. 对原文直接支持、背景材料、方法迁移和推断分别表达；不使用图谱关系、摘要或模型常识冒充正文实验结果。缺参数时给条件化方案与待补信息，不编造确定数值。
5. 主动“检查内容”优先识别数字、比较、因果、适用条件和强研究空白。对复合句拆成主张，并允许多个片段合并支持不同部分；保留每个主张的原文位置、来源与判定。
6. 超时、预算不足或非法模型输出记为未完成检查；不自动删除引用或把未知改为通过。需修改正文时作为显式修订，重新生成引用出现位置并使旧绑定失效。
7. 检索空白用“本轮所检索文献尚未覆盖”限定；强领域空白需要说明检索范围、关键词、时间及反例检查。内容检查与限定措辞均不承诺自动保证学术结论正确。

验收：完整版达到已约定章节范围；工程方案说明条件和缺项；数字/单位/比较对象可追到原文；局部缺失不表述成全领域不存在；主动检查后有效来源仍可查看，笔记审批和证据门禁保持原契约。

## 7. 风险与回退

- **AST 与数学转换顺序：** 原始偏移必须在转换前确定；优先覆盖实际组件，不能只验证字符串输出。回退展示实现时仍保留当前身份和伪造链接防护。
- **范围兼容：** 单篇或分类问答可能过去依赖隐式全库结果；改为显式范围后召回会变化，界面需明确实际范围和扩展入口，不能悄悄放宽。
- **检索与恢复一致性：** 分页遇索引更新、文献删除或范围变化需要判定续取失效，不能用旧游标继续后宣称覆盖完整。
- **语义核验误判与费用：** 保持用户主动触发、可取消和明确预算；长文只检查了一部分时显示实际覆盖，不能报告全文通过。
- **模型差异与完整性：** 自动化 fixture 可证明结构契约，不能替代 `deepseek-flash` 的自然回答质量；内容质量仍需真实样例和原文抽查。
- **数据与回滚：** 新状态优先为可选字段，恢复读取允许缺省；不迁移改写用户历史正文。实施后文档按实际提交写明回退办法，不预先承诺尚未实现的开关。
