# PaperQuay 大文库性能、阅读目录与 RAG 上下文切片方案

日期：2026-09-23  
状态：设计方案，尚未实施  
依据：当前工作区 v0.1.51 源码核查；未执行性能基准测试。本文中的优先级与默认参数为实施建议，不代表已取得的性能结果。源码行号是核查时的定位，后续可能变化。

## 1. 目标与范围

本计划统一处理四项需求：

1. 文献、RAG 索引、大 PDF 和解析成果不断增加后，改善应用启动、列表操作、文献打开与连续阅读的响应。
2. 阅读器增加章节目录索引，支持跳转和当前位置提示。
3. RAG 构建时保存目标切片与上下文的关系；构建完成后，检索命中或主动查看某个目标时，能够获得目标原文、前后切片、章节信息及可靠的位置引用。

4. 文献多选模式增加“全选”和“取消全选”，全选覆盖当前分类与搜索条件下的全部匹配文献，支持跨分页和虚拟列表。

第三项同时覆盖“索引时建立上下文关系”和“使用索引时取回上下文”。目标既可以是检索返回的 chunk，也可以是阅读器选中的结构块或文本范围。选择文本到切片的映射需要来源偏移支持，不能仅凭相似文本断言定位成功。

本次交付为方案文档。保留既有文献、解析结果、批注和向量；性能改造不以清空缓存、删除索引或全库重新 Embedding 为前提。

### 2.3 RAG 上下文能力

- `src/types/reader.ts:205` 的切片输入已有 `chunkId`、`chunkIndex`、`pageIndex` 等字段。
- `electron/backend/ragStore.cjs:521` 的 `rag_chunks` 已存切片顺序，且存在 `(document_key, source_type, chunk_index)` 索引；可以作为邻接范围查询的基础。
- `src/features/reader/readerRag.ts:377` 的 `buildExpandedHeadingSection` 会在命中 MinerU 标题后补充后续块，遇到下一个标题或达到限制时结束。
- `readerRag.ts:525` 的 `buildRagContextText` 依赖阅读器已加载的 `mineruBlocks` 与 `preparedSources`，当前扩展主要针对标题命中；普通正文命中没有通用前后文扩展。
- 当前标题扩展把补充块的 score 设为种子 score。新增设计应区分“直接检索命中”和“上下文补充”，避免让补充块表现为独立的相关度命中。
- 现有上下文装配用 `chunkId` 去重；推广至跨文献、跨来源时，必须使用文档、版本、来源与切片的复合身份。

现有标题补全是可复用基础；新能力应下沉到公共存储/服务层，让阅读问答、知识库检索、Agent 和笔记相关入口共享。其他调用方接入前应核查其现有参数和预算，避免仅改阅读器而遗漏其他入口。

## 3. 性能改造方案

### 3.1 启动与后台任务

1. 先创建窗口并显示基础界面，后端提供文库、RAG 等独立 readiness 状态。界面在相关服务就绪前不发起依赖请求，并显示初始化或迁移状态。
2. 将同步 RAG 数据库操作、向量汇总和迁移移入专用 Worker 或独立进程，由其统一拥有连接与写入队列。仅给现有函数增加 `async` 无法隔离同步工作。
3. 回填采用有界分批、检查点、可恢复迁移。未完成的新数据不冒充完整索引；失败能重试，旧可用数据在兼容范围内继续提供服务。
4. 交互读取优先于批量索引和迁移。限制磁盘与 Embedding 并发，支持任务取消；以实测长任务和队列等待调节批次。

### 3.2 文库读写

- 分类、搜索、排序和分页在 SQL 内完成，建立匹配查询模式的索引；采用稳定排序及唯一 ID 兜底，避免翻页重复或遗漏。
- 列表仅返回标题、作者摘要、年份和必要状态。选中后按需读取长摘要、笔记及附件详情。
- 总数、分类统计和“全库选择”使用独立查询或后端条件操作，不依赖前端 1000 条快照。
- 列表行窗口化，并保持选择、键盘导航和滚动恢复。
- 单项更新使用增量事务，批量操作使用批量事务，保留关联表完整性。
- 解析状态先检查当前可见项，其余限并发后台补齐；保留已有批量 IPC 和缓存机制。

### 3.2.1 多选文献时全选

**功能要求：**进入文献多选模式后，在列表工具栏提供全选复选框、“取消全选”和已选数量。全选覆盖当前分类、搜索及其他筛选条件下的全部匹配文献；无筛选时覆盖整个文库。明确显示“全选当前筛选结果（N 篇）”，不把当前可见行、当前页或已加载的最多 1000 条当作全部结果。

交互约定：

- 全选复选框支持未选、部分选择、全部选择三态；空结果时禁用。
- 点击全选后，翻页或滚动加载的匹配文献自动显示为选中；取消个别文献后进入部分选择状态，已选数量同步扣减。
- “取消全选”清空本次选择。退出多选模式清空选择，批量任务已提交的目标不受后续选择变化影响。
- 改变分类、搜索或其他筛选条件时清空选择，并提示选择范围已变更；仅改变排序、翻页或滚动时保留选择。
- 全选后可使用现有适用的批量操作，包括批量 RAG 索引。操作不适用的文献应显示跳过数量与原因，不得静默遗漏。

数据与执行方案：

- 普通多选使用文献 ID 集合；全选使用“查询条件快照或选择 token＋排除 ID 集合＋匹配数量”。避免为了全选而加载全部文献详情到前端。
- 后端提供完整匹配数量及分批枚举目标 ID 的能力。选择 token 绑定文库范围与选择时的匹配成员，或通过可靠快照机制达到同等效果；全选后新导入或新匹配的文献不自动加入本次选择。
- 后端提交批量任务时固定目标集合，并校验已删除或已失效的目标；返回实际目标数、跳过数与失败原因。后续列表刷新不改变运行中任务的目标集合。
- 大规模批量操作分批执行，提供进度、取消及结果汇总；沿用对应操作既有确认规则。
- 列表窗口化只影响行渲染，选择状态由稳定文献 ID 和统一选择模型维护，不依赖 DOM 是否挂载。

验收要求：

1. 无筛选全选全库；有分类或搜索条件时只选中全部匹配结果。
2. 超过 1000 条、跨分页、未加载行与窗口外行均纳入正确范围。
3. 验证三态、单项排除、重新全选、取消全选、空结果、排序保留及筛选变化清空。
4. 全选后导入、删除或修改文献时，数量与提交目标符合快照规则；批量任务不会因刷新而增加目标。
5. 批量 RAG 索引等操作覆盖所有适用目标，跳过、取消和失败均有明确结果。

### 3.3 打开文献与解析恢复

- 缓存路径用 stat/存在性检查，必要时探测少量文件头；真正格式错误由 PDF 加载错误路径处理。
- 远程 PDF 明确使用一种策略：下载完成后从本地打开，或远程先显示、后台保存。同步维护阅读历史、文件身份和缓存键，避免重复打开及位置丢失。
- PDF 首屏优先；JSON 解析、结构转换与文本提取移至 Worker。传输大结果时评估结构化克隆成本，逐步采用按页或按块段传输。
- 超长解析文档拆为元数据、章节索引和正文分段，目录不依赖全文渲染。

### 3.4 内存与标签生命周期

- 设定全局缓存预算，按估计字节占用管理 PDF、解析数据、裁剪图及缩略图。
- 活动标签保留资源，久未访问的标签保存页码、缩放、滚动和选择状态后休眠；正在保存或执行任务的标签单独处理。
- 关闭和淘汰时取消异步任务、销毁 PDF 对象并清理关联缓存；共享对象使用明确的引用所有权，避免一个消费者关闭影响另一个。
- 恢复标签时复用持久化阅读状态，验证批注与双栏联动不丢失。

## 4. 阅读目录方案

### 4.1 交互与来源

现有左侧栏增加“目录 / 缩略图”切换。目录支持层级折叠、标题搜索、当前位置高亮、跳转后返回上一个位置，并持久化每篇文献的展开状态。条目多时对目录列表窗口化。

来源优先级：

1. PDF 原生书签：复用当前 PDF proxy 的 `getOutline()` 和既有 `PDFLinkService.goToDestination()`。
2. 无原生书签时，从已有 MinerU 标题块提取目录；规范化时增加可选 `headingLevel`，未知层级平铺。
3. Markdown 标题可形成结构化正文目录；没有可靠页映射时仅跳正文，不显示推测的 PDF 页码。
4. 无书签且未解析时显示无目录状态，仍可用缩略图和页码导航。

### 4.2 数据与加载

建议统一目录项包含：`id`、`title`、`depth`、`source`、`children`，以及可选 `destination`、`pageIndex`、`blockId`、`bbox`、`sectionId`。目录模型与 RAG 章节映射共享规范化结果，避免两套章节判断不一致。

首屏后或首次展开时读取 outline。命名目标、页引用与坐标按需解析并缓存，避免打开文献时遍历所有目标。缓存绑定文档身份和版本，切换来源时忽略过期异步结果。

结构化目录从已有块提取，不重新读全文或触发 Markdown/KaTeX 渲染。重新解析后重建块映射；现有按页/块序号生成的 blockId 不能被当成跨版本永久 ID。

### 4.3 定位要求

- 原生目录保留 PDF destination 语义，包括命名目标、页引用、坐标与缩放。
- 结构块定位复用 `BlockViewer.tsx:720` 的虚拟窗口跳转：估算偏移、挂载目标、再精确滚动。
- 有可信页码和 bbox 时同步定位 PDF；否则只定位结构化正文。
- Markdown 回退当前可能把全部块放在一个逻辑页中，不能把 `pageIndex = 0` 当成真实 PDF 第一页。
- 错误目标给出局部提示，允许其他目录项继续使用；快速连续点击以最新请求为准。

## 5. RAG 目标上下文切片方案

### 5.1 预期体验

检索结果或目标块提供“查看上下文”入口，显示：

- 文献标题、来源、章节路径和可信页码范围；
- 前文切片、明确高亮的目标切片、后文切片；
- 每段原文对应的块/页定位入口；
- 按需“更多前文 / 更多后文”，以及截断或缺失原因。

索引任务完成后可查看切片预览和上述关系。索引进行中若目标尚未提交，返回“目标尚未就绪”，不把缺失误报为没有前后文。

问答和 Agent 可自动使用有界上下文；用户查看上下文与发送给模型是两个操作。仅展开预览不会自动调用模型或把额外正文发往外部服务。

### 5.2 切片与上下文分离

保留较小目标切片作为检索单元，前后文从已有正文按需取回。默认不为每个目标复制存储前后正文，也不把多个重叠大窗口分别向量化。

索引阶段：

1. 按规范化阅读顺序生成切片，去除页眉页脚等装饰噪声，保留真实来源关系。
2. 写入目标正文、顺序与定位元数据，并建立父块/章节映射。
3. 仅按既有切片策略生成向量；上下文关系不需要额外 Embedding 请求。
4. 按代次提交完整数据并标记 ready。查询只使用同一可用代次，禁止混合重新解析前后的切片。

检索阶段：先得到目标命中及其排名，再按预算取回上下文。补充上下文不改变原始检索得分和排序。

### 5.3 数据模型

优先复用 `rag_chunks`，新增字段需按实际 schema 迁移设计确定：

| 字段或关系 | 用途 |
| --- | --- |
| `documentKey + sourceType + generationId + chunkId` | 切片完整身份；generationId 是建议新增的索引代次概念 |
| `chunkIndex` | 同文档、来源、代次内的规范阅读顺序，允许有间隔 |
| `blockId` / 块映射表 | 切片所属原文块；跨块切片需支持一对多定位 |
| `sectionId`、章节父子关系 | 上级章节与扩展边界，共享阅读目录映射 |
| `pageStart` / `pageEnd`、可选 bbox | 多页范围及定位；未知为 null，不猜测页码 |
| `startOffset` / `endOffset`、`textVersion` | 在规范化源文本中的半开区间；统一按 JS UTF-16 code unit 计数，注明与原始文件字节偏移不同 |
| `contentHash`、解析/切片策略版本 | 判断可复用向量、检测过期映射 |
| 原文映射可用性 | 区分可靠范围映射、仅块级映射和仅顺序邻接 |

可通过有序范围查询获得前后项，无需同时维护冗余 prev/next 指针。扩展索引建议覆盖 `(document_key, source_type, generation_id, chunk_index)`；迁移期间保留旧索引兼容路径。

如果规范化导致字符偏移变化，应保存规范化文本与位置映射，或明确退化为块级定位。禁止用无法核实的偏移高亮原 PDF。

### 5.4 公共查询接口草案

以下是拟新增的逻辑服务接口，不代表当前已有 IPC 命令：

```ts
type ContextRequest = {
  documentKey: string;
  sourceType: string;
  generationId: string;
  chunkId: string;
  before?: number;       // 建议默认 1
  after?: number;        // 建议默认 1
  maxTokens?: number;    // 服务端仍强制上限
  boundary?: 'section' | 'document'; // 建议默认 section
};

type ContextSlice = {
  chunkId: string;
  chunkIndex: number;
  role: 'before' | 'target' | 'after';
  text: string;
  blockId?: string;
  pageStart: number | null;
  pageEnd: number | null;
};

type ContextResponse = {
  documentKey: string;
  sourceType: string;
  generationId: string;
  targetChunkId: string;
  status: 'ready' | 'not-ready' | 'not-found' | 'stale';
  sectionPath: string[];
  slices: ContextSlice[];
  truncated: boolean;
  truncationReason?: 'budget' | 'boundary' | 'incomplete-source';
  hasMoreBefore: boolean;
  hasMoreAfter: boolean;
};
```

由 ragStore 提供范围读取，公共 RAG 服务完成预算、去重和引用装配，再经现有桌面服务通道暴露。实现前检查实际服务路由、错误类型与取消机制，保持项目约定。

只查询指定文档、来源与代次。前文使用 `chunk_index < target ORDER BY chunk_index DESC LIMIT ?` 后恢复正序，后文使用相反方向；不能假设编号连续，也不能从其他文献补足数量。多个命中应批量查询，避免逐条 IPC 往返。

### 5.5 上下文选择与预算

1. 默认取目标前后各 1 个切片；章节已知时不跨章节，未知时允许同文档同来源按顺序扩展，并标注缺少章节信息。
2. 标题命中保留现有向后正文补全能力，与普通邻接统一装配。章节层级可靠时以当前章节范围为边界；不可靠时遇下一标题停止。
3. 图、表、公式若有显式关联的说明块，可优先补充这些关联。多栏 PDF 或 OCR 顺序不可靠时标注限制，不能保证序号邻接等同语义上下文。
4. 单目标窗口建议起始上限 1500 tokens；一次问答的扩展证据建议起始上限 6000 tokens。两者均为待调优参数，最终还受模型上下文、系统提示、历史和输出预留共同限制。
5. 有 tokenizer 时准确计数，否则使用保守估算并设置字符硬上限。目标超长时按相关范围截取并标明截断，不突破预算。
6. 重叠窗口合并但保留每个目标身份和命中信息。使用复合身份去重，正文按原文顺序组织，窗口组按检索排名分配预算，避免第一条耗尽全部上下文。
7. 切片 overlap 仅在有偏移或可靠公共前后缀时去重；没有依据时保留，不删除可能有语义作用的重复表述。
8. 上下文补充项标注 `retrievalRole: context`，记录 `expandedFrom`；不复制种子分数冒充独立命中。引用锚点保留真实目标位置，并允许查看补充段自己的位置。

### 5.6 阅读器、知识库与模型接入

- 阅读器：检索结果展开上下文，点击段落复用页/块定位；选中结构块按 blockId 找所属切片，多切片时以选择范围确定目标。
- 知识库搜索：无需先打开整篇 PDF 或加载全文 MinerU，直接查询持久化切片正文。
- 文献问答、Agent、笔记：共享上下文装配接口，在现有检索之后扩展，再按各入口预算进入 prompt；保留直接命中与补充来源的区分。
- Prompt 中将检索正文作为带来源的数据区块，正文中的指令不作为系统或工具操作指令。
- UI 只渲染当前上下文窗口。继续加载使用带文档版本的游标或边界切片身份，文档版本变化后要求刷新。

### 5.7 旧索引兼容与更新

- 最小版本先基于已有 `chunkIndex` 实现同文档、同来源的前后切片查询；缺少章节信息时明确降级。
- 旧数据未携带 generationId 时，在事务快照内读取，并结合现有索引 signature 校验；若完整性无法确认，返回限制状态，不拼接不确定版本的数据。
- 章节、偏移和关系可从持久化正文或解析缓存后台分批补齐，不能在启动时全库扫描。
- 如果切片正文、Embedding 模型和向量维度未变化，复用原向量；切片边界或文本发生变化时才重算受影响项。
- 新代次写完后原子切换，随后回收旧代次。兼顾临时磁盘占用并清理取消任务的未发布数据。
- 保持现有按 chunkId 计算缺口和断点续建能力；关系更新与索引 ready 状态一致提交，旧查询不会读到半批新关系。
- PDF 原文和 MinerU 是不同来源，默认不相互拼接为连续正文；未来若跨来源融合，必须有明确映射和独立出处。

## 7. 验收与测试

### 7.1 性能基线

记录环境、应用版本、冷/热缓存条件、文库数量、切片数量和文件大小；使用同一数据集重复测量，记录中位数与尾部延迟。

- 启动：进程启动到窗口可见、文库可操作、RAG 就绪的独立耗时。
- 打开：到首个 `pagerendered`、解析正文可交互、目录可操作的耗时。`PdfViewer.tsx` 中 `loading=false` 早于首屏实际绘制，不能代替该指标。
- 资源：主线程长任务、实际读取字节、峰值内存、后台队列等待，以及连续关闭或休眠后的内存变化。
- 数据集：小库与 1000 条以上文库；短论文、200 页级论文、500 页以上教材；有/无解析缓存，有/无待迁移 RAG 库。
- 改造后的结构要求：列表查询不再读取全库长正文；上下文查询按窗口读取；目录不增加一次 PDF 加载。具体毫秒和内存目标在测出基线后确定。

### 7.2 正确性矩阵

| 类别 | 必测情况 |
| --- | --- |
| 文库 | 超过 1000 条的分页、总数、分类、排序、全选和批量操作；增量写入后关联信息一致 |
| 目录 | 命名/数组 destination、坏页引用、深层目录、重复标题、无书签、未知层级、无真实 PDF 页码 |
| 阅读联动 | 离屏块跳转、连续点击、快速换文献、返回位置、重新解析、批注与双栏联动 |
| 上下文邻接 | 首尾切片、编号间隔、单切片文档、普通正文与标题命中、跨页段落和章节边界 |
| 来源隔离 | 不同文献同 chunkId、PDF/MinerU 双来源、多代次并存，均不发生错误拼接 |
| 预算与引用 | 重叠窗口合并、超长目标、中英文与公式、截断标记、直接命中与补充段位置一致 |
| 更新与兼容 | 旧索引降级、部分索引、取消/续建、重解析后旧请求失效、迁移失败恢复 |
| 跨入口 | 阅读问答、知识库、Agent 和笔记取得一致来源；无需加载整篇文档才可读邻接上下文 |
| 生命周期 | 多篇大文献开关与休眠、资源释放、共享对象不被提前销毁 |

实施时增加有意义的数据库集成测试、上下文装配测试与必要的阅读交互测试，执行项目要求的构建和相关回归。本文写入未运行这些功能测试，也不表示上述功能已经完成。

## 8. 完成定义

四个目标均需有可观察结果：大库与大文献操作有基线对比，目录能可靠定位，目标切片能取回有界且可追溯的上下文，多选全选能覆盖当前筛选下全部文献并正确执行跨分页批量操作。现有索引和解析成果能够平滑兼容；缺少可靠页码、章节或版本关系时明确降级。最终交付应附实际测试结果、仍存在的限制及对应后续工作。
