## 一、采用方案

先修复失败时丢失用户问题，再增加用户与助手消息复制。失败处理只移除本次空助手占位，保留当前会话状态。复制使用清理后、引用链接注入前的消息源码。

| 上游提交 | 处理 | 优先级 | 本地依据 |
| --- | --- | --- | --- |
| `56efb70` | 吸收保留用户消息的目标，重写失败收尾 | P1：用户输入丢失 | 本地 `catch` 仍回滚整个会话；上游仍保留旧选中会话和附件恢复逻辑 |
| `a77bb06` | 增加复制功能，复用工具并补失败反馈 | P2：功能补充 | 本地没有消息复制入口；上游重复剪贴板逻辑且使用 10px 字号 |
| `1d65fdb` | 不单独移植 | — | 相对第一父提交的差异与上述两次提交累计差异一致 |

实施默认采用以下交互：

1. 无回答失败时，保留问题、附件引用和历史消息。
2. 失败后维持当前选中会话，不恢复发送前的选择。
3. 附件保留在消息中，不自动回填输入框。失败收尾不得覆盖用户新写的草稿和新加的附件。
4. 有非空回答后失败时，保留已生成回答，沿用现有错误提示。
5. 助手使用“复制原始内容”文字按钮，用户使用复制图标按钮。
6. 两项功能分别提交，发布时可随同一版本交付。

说明：以上是修订后的实施默认值。本轮不修改应用代码，不提交、合并、推送或发布。

### 4.2 纯函数契约

```ts
export function removeFailedQaAssistantPlaceholder(
  sessions: DocumentChatSession[],
  sessionId: string,
  assistantMessageId: string,
): DocumentChatSession[];
```

函数只处理当前数组，遵守以下规则：

1. 目标会话不存在时，返回原数组，不追加会话。
2. 目标消息不存在、不是助手或含非空内容时，返回原数组。
3. 目标消息为空或只有空白时，只移除该消息。
4. 保留用户问题、附件和其他消息，保留会话 ID、标题、创建时间及其他字段。
5. 若占位是末条消息，用移除后的末条消息时间更新 `updatedAt`；否则保留当前 `updatedAt`。
6. 无消息剩余时，使用会话创建时间作为 `updatedAt`。发送路径正常情况下仍有用户问题。
7. 不修改传入数组、会话或消息对象；未命中时保留原数组引用。

标题已在发送时按 `nextMessages` 生成，失败收尾无需再次计算。会话创建时间也已在 `pendingSession` 中归一化。

### 4.3 发送回调修改

保留 `pendingSession` 和流式更新流程。仅替换无回答失败分支：

```ts
if (!streamedAnswer.trim() && sessionStillActive) {
  setQaSessions((current) =>
    removeFailedQaAssistantPlaceholder(
      current,
      currentSession.id,
      nextAssistantMessage.id,
    ),
  );
}
```

删除 `hadCurrentSession`、`previousSession`、`previousSelectedSessionId` 和 `previousAttachments`。从回调依赖数组移除不再读取的 `qaSessions`、`selectedQaSessionId`。

失败分支不调用 `setSelectedQaSessionId`、`setQaInput` 或 `setQaAttachments`。用户停留原会话时，问题继续可见；用户切到其他会话时，不抢回选择或恢复旧附件。

保持工作区检查、现有 `qaError` 和 `finally` 的运行标记清理。后台失败提示仍是共享状态，暂不增加每会话错误字段。

注意：本方案没有解决“切到其他文档后又返回”的旧请求归属问题。当前 workspace 检查无法区分同一文档的两次加载，流式更新也存在此限制。实施时必须回归该路径；若出现旧请求覆盖新状态，记录独立缺陷，完成隔离修复后才能宣称跨文档异步验收通过。

### 4.4 附件与重试边界

附件只保留在本次用户消息中。输入框保持用户当前草稿，不自动恢复发送前附件。

当前没有“一键重试”操作。再次发送需要重新填写问题，并按需重新附加文件。复制功能完成后，可复制原问题再发送；该操作会新增一条用户消息。

重开文档后，验收问题文本、标题和附件元数据。图片数据及文本附件正文仍受现有持久化裁剪规则限制。新增附件持久化或重试按钮须另列需求。

### 5.2 剪贴板工具契约

```ts
export async function copyTextToClipboard(
  value: string,
  options?: { preserveWhitespace?: boolean },
): Promise<boolean>;
```

- 默认保持旧笔记行为：trim 后写入。现有调用方无需改 import，也无需消费返回值。
- `preserveWhitespace: true` 时，只用 trim 判断是否为空，写入原字符串。阅读器使用该选项。
- 空文本返回 `false`，不访问剪贴板，不显示成功反馈。
- 按 Electron、`navigator.clipboard`、textarea 顺序尝试。每条路径不可用或失败后再尝试下一条。
- 写入成功返回 `true`。全部路径失败时抛错，不吞掉失败。
- textarea 路径检查 `document.execCommand('copy')` 的布尔结果。使用 `finally` 移除临时元素，并恢复原焦点及可恢复的选区。
- 在工具内部按需访问浏览器全局对象，避免导入模块时访问 `window`，便于 Node 测试。
- 不修改 Electron 主进程或 preload 接口。

### 5.3 内容选择

| 消息类型 | 复制内容 | 说明 |
| --- | --- | --- |
| 用户 | `message.content` | 保留存储内容中的首尾空白；发送入口本身已有 trim |
| 助手 Markdown | `cleanQaAssistantOutput(message.content).trim()` | 保留 Markdown、公式、代码块和回答原有引用编号 |
| 助手 HTML | 同上 | 复制 HTML 源码；不提取预览正文 |
| 仅空白或清理后为空 | 不复制 | 不显示成功；空助手占位不显示复制入口 |

复制不附加模型、时间、检索提示、附件内容或引用芯片。回答中的原始引用标记保留；渲染阶段注入的导航链接不进入剪贴板。

说明：“原始内容”指清理后的消息源码，不承诺返回模型网络响应原文。

### 5.4 按钮与反馈

1. 复用 `Copy`、`Check` 图标和现有操作栏样式。文字至少 11px，颜色使用 `--pq-*`。
2. 助手操作按钮放入统一的 `ml-auto` 容器。容器内并排显示复制与保存，窄栏允许换行。
3. 用户时间行增加图标按钮，提供中英文 `title` 和 `aria-label`。
4. 两类操作栏均支持 hover 和 `focus-within` 显示，保留 `focus-visible`。
5. 复制成功后显示“已复制 / Copied”，持续约 1.6 秒。图标按钮同步更新可访问名称。
6. 复制失败时，在消息行显示“复制失败，请重试 / Copy failed. Try again.”，使用 `role="status"` 或等效可访问状态。不得显示已复制。
7. 不新增 toast 或全局状态；复制错误不得写入问答的 `qaError`。

`handleCopyMessage` 捕获点击时的内容快照。流式回答允许复制，复制内容为点击时已生成的文字；新 token 不改变本次载荷。

使用组件局部状态记录反馈消息 ID，并用 ref 保存定时器和复制请求序号。开始新复制、切换会话或卸载时，清理定时器并使旧序号失效。异步返回后先核对序号，再更新反馈，避免慢请求覆盖新反馈。组件卸载后不得更新状态。

说明：请求序号只保护反馈。系统剪贴板的异步写入仍可能按完成顺序覆盖，不能承诺跨点击的最终顺序。

| 发送后编辑下一条草稿或添加附件 | 失败收尾不覆盖新输入和新附件 |
| 失败后重新打开文档 | 问题、会话标题、附件元数据可恢复；不要求已裁剪附件正文恢复 |
| 同文档双会话并发 | 一个请求失败不修改另一个请求的消息、选择或运行标记 |
| 切换文档后失败，以及切走再返回 | 记录旧请求对消息、草稿、错误和运行标记的影响；发现覆盖时按 4.3 处理 |
| Markdown、公式、代码块、引用 | 剪贴板文本符合 5.3，引用不变成应用导航 URL |
| HTML 与流式回答 | 复制源码和点击时快照，不复制预览 DOM |
| 复制 A 后立即复制 B、切换会话、卸载 | 旧任务不覆盖新反馈；无残留定时器或卸载后状态更新 |
| 剪贴板拒绝写入 | 显示失败，保留可重试入口，不出现“已复制” |
| 键盘、窄栏、浅色与深色 | Tab 可到达按钮，焦点可见，中英文文案不遮挡模型和时间 |
| 侧栏与浮动窗口 | 两处复制和错误反馈一致，保存为笔记仍可用 |
| 笔记复制回归 | 原有 4 个模块继续通过兼容导出复制，默认 trim 行为不变 |

故障复现优先用隔离配置和本地失败服务或 mock 流。不得改用户真实模型配置来制造失败，也不依赖外网临时断开来复现流式中断。

桌面验收使用本次构建和隔离数据目录。隔离文献库、笔记 vault、设置、RAG 与网络集成，不让测试写入个人文库。若开发启动仍出现已记录的 rc=3，按项目地图使用新输出目录打包，再复制到临时目录启动。记录实际构建、启动路径和数据目录；已安装旧版截图不能证明本轮行为。

截图至少覆盖浅色、深色、窄栏、键盘焦点、复制成功及失败。证据放本轮独立验证目录，不改既有 `.verification-*` 内容。
