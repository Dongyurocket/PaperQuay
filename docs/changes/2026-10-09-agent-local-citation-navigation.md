# 2026-10-09 - Agent 来源跳转与可选内容检查

## 现象

0.4.7 实测中，检索出的有效来源因逐句核验未通过或核验响应不可用，正文大量显示未验证标记，片段参考文献列表缺失。推荐回答反复使用“一篇研究”等描述，执行轨迹过长，难以辨认推荐的论文。

## 根因

来源身份、内容支撑判断与跳转权限共用核验状态。每个片段单独核验整个复合句，即使片段分别支撑不同部分也可能不通过；响应不可用同样阻止来源查看。共享提示词还禁止手写题名，影响推荐回答可读性。

## 修改

- 本地解析精确 token 与当前消息的 canonical 来源；按首次出现编号，来源可解析即可查看，正常生成不调用核验模型。未知或歧义 token、同句重复、代码中的 token、未完成 token 和历史裸数字不获得链接。
- 独立的来源绑定返回 `source-resolved` / `unverified`，不产生语义支持判定。旧核验结果仅在正文位置、token 和句子一致时用于提示；失效或重复的保存结果不能授权来源。
- 「检查内容」主动触发原有规则和模型检查。支撑不足、冲突、题名/页码不符、超时和无效响应均不隐藏有效来源。无论正文写了什么页码，跳转始终使用 canonical paper/page/block，不采信模型手写位置。
- 文末列表使用本地文献记录的题名、作者、年份、刊物，缺失字段省略。推荐提示要求复制真实题名及可用年份，解释具体相关性，区分直接证据、背景与候选文献。
- 来源/内容明细及完整执行轨迹默认折叠。生成、保存、恢复和笔记写入契约没有迁移；笔记证据检查保持独立。
- Zotero 同步测试使用独立运行状态注入，避免真实桌面进程阻止临时数据库 fixture；产品并行写入护栏不变。
