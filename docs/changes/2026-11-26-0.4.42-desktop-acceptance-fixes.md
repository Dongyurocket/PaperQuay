对应验收报告：`docs/changes/2026-11-26-v0.4.41-desktop-acceptance.md`（PASS 7 / 部分 10 / FAIL 3 / BLOCKED 20；P0 0、P1 2、P2 2）。

## 1. P1-01 知识图谱画布空白 + `Cannot read properties of null (reading 'value')`

### 现象

- 侧栏显示 196 节点 / 845 关系，语义覆盖 169/196，布局 fcose 1016ms、首帧 14ms 都有记录，但画布上没有任何节点与边；Canvas 与 WebGL 两种渲染器都一样。
- 切换主题或切标签进入图谱工作区时命中错误边界：`Graph workspace failed to load — Cannot read properties of null (reading 'value')`。

### 根因

`src/features/graph/graphPresentation.ts` 里两个判断不一致：

- `buildProgressRingImage(progress)` 按 5% 分桶，`Math.round(clamp*20) <= 0`（进度 < 2.5%）返回空串；
- `hasProgress` 却写成 `progress > 0 ? 1 : 0`。

于是进度 0.523% 的论文节点满足 `hasProgress = 1`、`progressImage = ''`，命中样式 `node[hasProgress = 1]` 的 `background-image: data(progressImage)`。cytoscape 的 `parseImpl` 对 `multiple` 类型属性做单值解析，空串返回 `null`，随后 `hasEnum = hasEnum || is.string(p.value)` 对 `null` 取 `.value` 抛错。该异常发生在 `effectiveOpacity → parsedStyle → applyContextStyle` 的绘制路径上，第一个元素就中断，canvas 一个像素都画不出来。

同一异常会在 `cy.fit()`（React effect 内同步触发绘制）时上抛，被 `App.tsx` 的 workspace 错误边界接住，即验收看到的崩溃文案。

### 证据（0.4.41 安装版 + 一次性 profile 副本 + DevTools 协议）

- `cy.nodes()` 196、`cy.edges()` 845；`cy.zoom()` 0.576、pan 与 extent 正常。
- 三个 canvas 均为 1080×832 CSS 尺寸，`getImageData` 非透明像素 0。
- 逐规则挂载：仅 `node[hasProgress = 1]` 抛 `Cannot read properties of null (reading 'value')`，其余 26 条规则正常。
- `hasProgress=1 && progressImage===''` 的节点恰好 1 个：`paper:paper_mtst6k8n_e6f8d8cb`，`readingProgress = 0.005230672664504656`。

### 修改

- `src/features/graph/graphPresentation.ts`：先算 `progressImage`，`hasProgress` 由图片是否为空决定。
- `tests/graphPresentation.test.ts`：0.523% 与 24% 两个边界断言；遍历所有元素，`hasProgress === 1` 时 `progressImage` 必须非空。
- `tests/graphStyles.test.ts`：用 headless cytoscape 加载真实样式表，对每个节点调用 `parsedStyle('background-image')`，断言不抛错。该用例在 0.4.41 的取值下会复现同一异常（已单独验证）。

## 2. P1-02 设置弹窗侧栏溢出，「AI 模型」不可达

### 根因

1. 布局：侧栏列表 `min-h-0 flex-1 overflow-y-auto`、底部「当前翻译缓存」条 `shrink-0`。窗口较矮时列表被压缩到只能露出 6 个多分页，最后一个「AI 模型」正好被底部信息条压住；滚动条是 10px 半透明、列表 `pr-1` 只留 4px，几乎不可见。
2. 滚轮委托从未挂载：`useWheelScrollDelegate` 的 effect 依赖 `[ignoreSelector, rootRef, targetSelector]`，而 `ReaderPreferencesWindow` 在 `open=false` 时返回 `null`，组件挂载时 `rootRef.current === null`，之后 `open` 变 true 也不会重跑 effect。

### 修改

- `src/hooks/useWheelScrollDelegate.ts`：新增 `enabled` 选项（默认 true），并加入 effect 依赖。
- `src/features/reader/ReaderPreferencesWindow.tsx`：传入 `enabled: open`；列表加 `pb-3`、`pq-preferences-section-list`；底部信息条上边距 4→3。
- `src/app/index.css`：新增 `.pq-preferences-section-list`，固定 `scrollbar-gutter` 并加深滑块。

## 3. P2-01 笔记「任务列表」点击无响应

### 根因

该按钮是 ProseMirror 的 `toggleTaskList()` 格式化命令，不是任务中心面板。验收笔记正文全部是引用摘录块（atom 节点），光标落在其中时命令返回 false，没有事务、没有提示，表现为「点了没反应」。

### 修改

- 新增 `src/features/notes/noteTaskList.ts`：`toggleTaskListAtSelection(editor)`，先 `toggleTaskList()`，失败时插入 `taskList > taskItem > paragraph`，返回 `toggled | inserted | unavailable`。
- `src/features/notes/NoteEditorToolbar.tsx`：工具栏按钮改用该入口，`unavailable` 时提示。
- `src/features/notes/NoteBlockControls.tsx`：块菜单共用同一入口。

## 4. P2-02 筛选无结果沿用「空库」文案

### 根因

`LiteraturePaperList.tsx` 的空态只判断 `papers.length === 0`，不看 `filters` / `searchQuery`。

### 修改

- `src/features/literature/components/LiteraturePaperList.tsx`：逐字段判断是否有筛选/搜索；有筛选时显示「没有符合条件的文献」+「清除筛选」（重置为 `DEFAULT_LIBRARY_FILTERS` 并清空搜索）+「导入 PDF」。
- `tests/literaturePaperListA11y.test.ts`：新增筛选空态断言与清除按钮回调断言；`tests/literaturePaperListStability.test.ts` 的图标桩补 `SearchX`。

## 5. OBS-01 MinerU 徽标 / 筛选恒为 0（结论：隔离副本环境问题）

- 徽标判定是「MinerU 输出文件是否存在」（`mineruOutputPathCandidatesForPaper`），不是 DB 的 `paper_processing_status.mineru_status`。
- 验收副本的 `mineruCacheDir` 仍指向真实 profile 的绝对路径，副本里未授权，`localPathsExist` 全部返回 false，于是全部「未解析」。
- 复核：把副本 `.settings/paperquay.config.json` 的 `mineruCacheDir` 指到副本自己的 `.mineru-cache`（197 个目录）后启动，首屏 12 行全部显示「MinerU 已解析」，0 行「未解析」。
- **结论：不是产品缺陷**，后续验收副本需把 MinerU 缓存目录指向副本内路径。

## 6. OBS-02 笔记保存后仍显示「未保存」

- 0.4.41 安装版 + 副本上多次尝试（输入后保存、节流窗口内立即保存、Ctrl+Z 后保存、改标题后保存）均未复现，保存后徽标正常消失、DB 与编辑器 JSON 完全一致。
- 代码审查发现两处归一化不一致，会造成「保存后签名永远不相等」的永久脏标记：
  - 后端用 `cleanString`（trim）落库 `contentText`，前端 `fastContentSignature` 用原文哈希；
  - 后端把标签存成数组再 `join`，前端用原始字符串（`a,b` 与 `a, b` 不同）。
- 修改：`src/features/notes/noteEditorUtils.ts` 的 `fastContentSignature` 先 trim 文本，`fastSignatureFromContent` 用 `normalizeTagInput` 归一化标签后比较。
