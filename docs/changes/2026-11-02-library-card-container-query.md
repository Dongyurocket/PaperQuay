# 2026-11-02 - 文库卡片在窄容器下标题消失

## 现象

文库页三栏布局中，把左侧分类栏或右侧详情栏拖宽（或把窗口缩到较小尺寸）后，文献卡片会"空壳化"：

- 标题、副标题、作者、PDF 路径全部看不见，只剩年份和导入日期；
- 「MinerU 已解析」「RAG 已索引」「概览已生成」三个徽标被挤成竖排长条；
- 卡片被撑到约 300px 高，但绝大部分是空白；
- 卡片内出现一段看不出含义的迷你折线（阅读热力列被压窄后的形态）。

实测条件：窗口 1568 CSS px，分类栏 377 + 详情栏 628，列表容器约 445px。

## 根因

卡片用固定列 grid（`src/features/literature/components/LiteraturePaperList.tsx:694`，改动前）：

```text
grid-cols-[28px_minmax(0,1fr)_minmax(128px,160px)_72px_96px] max-[900px]:grid-cols-[28px_minmax(0,1fr)_64px_86px]
```

1. 固定列开销 `28 + (128~160) + 72 + 96 = 324~356px`，加 4 个 12px 间距共 **372~404px**。列表容器 445px 时，留给 `1fr` 标题列只有 41~73px，标题/作者/路径都带 `truncate`，被截成不可见。
2. 降级分支用的是 `max-[900px]:`，这是**视口媒体查询**。该区域变窄的原因是容器（侧栏拖拽）而不是视口，窗口宽 1568px 时永不命中。
3. 徽标容器是 `flex-wrap`，列宽不足时逐行堆叠，把卡片高度撑到 300px；徽标文字在 ~30px 宽的胶囊内被强制折行，形成竖排。
4. 阅读热力列默认开启（`LiteratureLibraryView.tsx:332` 的 `showReadingHeatmap = true`），所以 5 列布局是默认路径。
5. 窗口最小宽 1040 时列表被 `minmax(360px,1fr)` 压在 360px，固定列开销 372~404px 已经超出，**必然塌陷并横向溢出**，与用户是否调整过侧栏无关。

## 修改

改用**容器查询**，断点判断对象从视口换成列表容器的实际宽度。

- `LiteraturePaperList.tsx`：滚动容器加 `pq-paper-list` 类；卡片类名从 Tailwind 的 `grid-cols-[...]` 改为 `pq-paper-row-card`（开启热力列时追加 `pq-paper-row-card--heatmap`）；热力/年份/日期三个列位分别加 `pq-card-heatmap`、`pq-card-year`、`pq-card-date`；两个徽标行加 `pq-card-badges`；年份与日期文字色从硬编码 `slate-*` 改为 `--pq-text-muted` / `--pq-text-faint`。
- `src/app/index.css`：新增 `.pq-paper-list { container-type: inline-size; container-name: paperlist }` 与四级级联：<520px 只留手柄+标题，≥520px 恢复年份，≥640px 恢复日期，≥780px 恢复热力列（仅开启时）；`.pq-card-badges > span { flex-shrink: 0; white-space: nowrap }` 禁止徽标内部折行。

级联后标题列在任意容器宽度下都有足够空间，窄宽度改为收起次要列而不是压缩标题。

- 容器查询阈值按内容盒计算，列表容器自带 `p-3`（24px），因此实际触发点比标称值晚约 24px，符合"按可用宽度判断"的意图。

### 实机验证（2026-11-02，Computer Use）

用当前代码打包为 `win-unpacked` 后启动真实应用（窗口 1568 CSS px，侧栏 377 + 详情栏 628，列表容器约 445px，即原故障宽度）：

- 每条卡片正常显示：标题（单行 + 省略号）、英文副标题、作者、三个徽标横排一行、PDF 路径；
- 卡片高约 140px，一屏可见 5 条（修复前约 300px 高、仅见 1.5 条）；
- 年份/导入日期/阅读热力列在该宽度下按设计收起，不再有被压窄的迷你曲线；
- 点击卡片可正常切换右侧详情面板（点击第 2 条后详情切换为该文献及其翻译/解析状态），说明新列布局未影响点击通路；拖拽把手 ⠿ 正常渲染。
- 未覆盖：Ctrl 多选、拖拽排序、拖到分类这三项需要修饰键或拖拽手势，Cua 在该窗口的后台输入不支持修饰键（返回 `refused`），未做验证；本次未改动任何事件处理。
