# 摘录提炼预览与多模态重识别

## 现象

痛点 8 的摘录提炼原来在两步 CoT 完成后直接创建或追加笔记，用户无法在写入前对照原始识别文本和提炼结果。公式、表格等区域也只能把现有文本识别结果直接送入提炼，识别错误会污染摘录卡的原文快照。

## 修改

- 提炼入口现在默认打开可复用的并排预览面板：左侧显示原始识别文本，右侧显示可编辑的标题和提炼正文。只有“确认并写入”或保留的“直接保存”旁路会落库，取消只关闭面板并清理状态。
- 追加到已有摘录卡也先进入预览；预览对应追加后的完整正文，确认时新锚点和新提炼段插入“💭 我的想法：”之前，已有锚点对象保持不变。
- 保留旧的直接模式作为预览完成后的“直接保存”按钮，默认流程仍是预览确认。直接保存不会丢弃已经完成并由用户选择的多模态重识别结果。
- 预览面板中的“AI 重识别公式/表格区域”复用 `getPdfBlockCropDataUrl()` 切出 PDF 区域，并复用共享 Agent 模型预设和既有视觉 IPC。只有配置了 `supportsVision: true` 的模型且选区存在可用区域切片时可用；模型不支持视觉时置灰并说明原因。
- 重识别结果进入两步 CoT 的第一步输入。视觉调用失败、切片失败或返回空结果时自动回退原始纯文本，预览中显示回退提示；回退路径不写入 `aiEnhanced`。
- 用户确认使用重识别结果后，新增锚点的原文快照写入 `aiEnhanced: true`。后端锚点归一化、Tiptap 锚点节点和编辑器展示均保留该标记，并显示“AI 重识别”来源标识。锚点仍只增不改，已有快照不被静默改写。
- 预览状态机和提交数据组装抽为 `noteDistillPreview.ts`，可直接由 `node --test` 测试；覆盖确认/取消、追加组装、重识别失败回退和 `aiEnhanced` 写入/展示逻辑。
