# 2026-09-17 - 正文结构、视觉区块重析与 PaddleOCR 任务状态修复

## 现象

- 含 `V_{net}`、`\gamma`、`\theta` 等行内公式的普通正文被显示成符号表。
- 单块 AI 重新识别需要手动选择结构模式，实际请求没有发送原 PDF 图片；修复内容仅存于组件状态，部分表格和图片分支没有显示覆盖值。
- PaddleOCR 云端任务及本地缓存已经完成后，界面可能仍显示运行中；关闭阅读标签页再等待任务完成时，父级任务状态缺少可靠终态来源。

## 根因

- 通用 Markdown 归一化和 MinerU 默认正文路径调用了启发式符号表重建。普通英文大写词与数学变量可以误触发规则，LaTeX 命令也可能被错误拆分。
- AI 重析只传入抽取文本，没有调用现有 PDF.js bbox 切片能力。渲染分支和修复保存的生命周期不一致。
- 解析进度依赖阅读组件局部状态及 effect 同步；组件卸载后，局部状态无法继续驱动父级。原网络超时只在轮询循环边界检查，不能终止卡住的请求或响应读取；图片资源串行下载也会延长云端识别后的等待。
- 上述代码路径已确认，但没有实际复现用户那一次云端请求，因此不把某一条路径认定为该次故障的唯一原因。

## 修改

### 保留正文结构

- 从通用 Markdown 和 MinerU 正文渲染中移除自动符号表重建。
- 保留显式旧工具的有限兼容能力，仅对明确标题下的纯文本候选处理；数学标记、表格、代码及不确定输入原样保留。
- 添加用户截图段落、密集变量、符号表标题和已有 Markdown 的回归测试。

### 统一 AI 重析

- 删除结构模式选择；以原 PDF bbox 切片为主要证据，OCR 文本作为辅助参考，由模型保持段落、表格和公式的原始结构。
- 弹窗预览实际发送的切片。模型未标记视觉能力、PDF/bbox 缺失或裁剪失败时，明确标注“仅文本修复”及原因，由用户手动启动。
- 通过现有 API 适配层支持 Chat Completions 的 `image_url` 和 Responses 的 `input_image`。视觉请求失败直接报错，不自动追加一次纯文本请求。
- 保存应用、恢复原文与 Markdown 预览保留。覆盖值按文献来源、解析路径与完整原始 blocks 的 SHA-256 版本存入 localStorage；存储失败明确报错，解析内容变化时不会错误套用旧修复。
- 表格、图片及公式区块也显示覆盖内容。切片缓存键纳入页码、bbox、坐标系和页尺寸。
- 覆盖只影响本地阅读视图，不改写原 OCR 缓存、RAG 索引或已有译文；双语视图标明译文基于原始识别。

### PaddleOCR 生命周期

- 增加后端任务注册表和常驻前端任务订阅，以文献标识、任务 ID 和递增修订号同步进度，不依赖阅读标签页是否挂载。
- 展示提交、云端识别、下载结果、下载图片、保存及分卷合并等阶段；以后端保存完成为终态依据，不根据旧缓存推断新任务完成。
- 网络期限覆盖请求头与响应正文读取，任务总期限贯穿多个云端阶段；图片下载使用有界并发。
- 同一文献的并发 PaddleOCR 任务被拒绝，旧快照与过期进度不能回退任务状态。
