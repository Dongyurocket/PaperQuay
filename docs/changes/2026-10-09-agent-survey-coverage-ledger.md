# 2026-10-09 - Agent 调研覆盖台账

## 现象

完整调研可以记录候选文献数和最终引用，但无法区分摘要筛选、正文检索、重点阅读、引用、无关、未解析和失败状态，也无法按子问题保留证据缺口。中断后恢复时，旧 checkpoint 只能恢复阶段文本和引用，不能说明尚未完成的覆盖范围。

## 根因

对比调研能力的 artifacts 没有覆盖台账契约；恢复读取也只校验阶段字符串和引用。候选数或报告成功不能作为“全部读完”的证据。

## 修改

- 新增可序列化的 `agentSurveyCoverage` 台账，分开记录候选、摘要已看、正文检索、重点阅读和实际引用。空命中、缺少文档、无法读取文档、检索失败及文献任务失败分别记录，不把切片命中或重点摘段阅读写成全文已读。
- 台账按子问题保存候选文献、已完成/失败文献、canonical 引用 ID 和证据缺口。论文数与子问题数预算限制实际批次；token 与耗时采用测量值，显式继续时更新本轮预算基线，并保留累计用量和既有覆盖事实。
- `ComparativeSurveyArtifacts` 保存 coverage 与尚未完成合成的 `researchContexts`。批次会保存已完成的正文摘段及来源后再传播取消；阶段 checkpoint、恢复入口和最终结果提供同一覆盖台账及 `coverageSummary`，部分完成、取消、失败和预算停止均可解释。
- research 合成为空、`finish_reason=length`、缺少当前子问题有效 canonical 引用或含非法引用时保持部分完成，保留待合成正文、来源、此前研究笔记和实测用量；恢复成功后才清空上下文并标记重点阅读完成。合成中断时 report 使用本地部分结果，不另请求模型补造研究证据。
- 最终引用数只统计最终回答中 `source-resolved` 的本地引用绑定；检索或中间研究笔记中的引用只作为候选证据，不自动计入最终已引用文献数。
- 旧或损坏 checkpoint 的 coverage、执行预算和摘段经过归一化，缺失字段保持未知，不把历史候选数推断为已读数。恢复保留 canonical 身份和未合成正文，继续批次跳过已完成项，失败或未解决项仍可重试。

## 验证

- 覆盖台账、能力阶段和恢复回归包含状态区分、子问题证据缺口、实际预算与继续基线、176 篇候选的隔离批次、失败重试、取消后证据保留、未合成摘段恢复及损坏历史数据归一化。
- 真实服务 research/report 处理器补充 9 项回归，验证空合成、非空 length、无引用、未知/重复/旧数字/代码内引用的恢复与实际模型计量；均已纳入最后 828/828 全量测试。
- 2026-10-10 工作区验证中，`npx.cmd tsc --noEmit` 已通过。相关结构化预算、续取和截断补充回归 `tests/agentToolContentContinuation.test.ts`、`tests/agentLoopTruncation.test.ts`、`tests/agentPaperScope.test.ts` 共 26 项通过。
- 最新全量构建、测试及真实桌面模型验收统一记录在 [Agent 检索、渲染与交付质量综合记录](2026-10-09-agent-retrieval-rendering-delivery-quality.md)。隔离批次只验证调度和恢复契约，不能作为 176 篇真实文库已完成全文调研的证据。
