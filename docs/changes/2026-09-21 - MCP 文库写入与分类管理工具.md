# 2026-09-21 - MCP 文库写入与分类管理工具

## 现象

PaperQuay 的 MCP 服务（`bin/paperquay-mcp.cjs`）此前只能只读检索知识库，外部 Agent 无法通过 MCP 完成导入 PDF、管理分类、更新元数据、删除文献等文库管理操作；唯一的写入口是 Zotero 选择性同步。此外，桌面应用以「内存态 + 整体落盘」模型持久化文库：应用运行时任何 MCP 外部写入都会在应用下一次保存时被静默整体覆盖，造成数据丢失且无提示。

## 根因

- MCP 服务仅注册了 9 个检索/同步工具，未覆盖 `electron/backend/libraryCommands.cjs` 中已有的文库写入语义（`library_import_pdfs`、`library_create/update/delete_category`、`library_update_paper`、`library_delete_paper` 等）。
- MCP 服务与应用各自独立持有 SQLite 连接，但应用的 `store.save()` 是「清空 + 全量重插」，外部写入对应用内存态不可见，存在 lost-update 风险；此前没有任何进程级防护。

## 修改

`electron/mcp/knowledgeMcpService.cjs`：

- 新增 `detectDesktopAppRunning()`：Windows 用 `tasklist` 检测 `PaperQuay.exe`，macOS/Linux 用 `pgrep -x PaperQuay`；探测失败返回 `null`（放行但附 `warning`）。构造函数支持注入 `isAppRunning` 便于测试。
- 新增写护栏 `assertWritable` / `withWritableLibrary`：所有写工具先检测桌面应用进程，运行时显式拒绝并提示关闭应用；`allowWhileAppRunning: true` 可强制覆盖；环境变量 `PAPERQUAY_MCP_WRITE=off` 全局禁用写入（优先级最高）。写入统一复用 `createLibraryStore → load → mutate → save → close` 路径，与应用语义一致。
- 新增方法：`listCategories`（只读，含后代分类文献计数）、`importPdfs`（内容哈希查重、copy/move/keep、按名称自动建分类、逐文件错误收集，不触发 Crossref 网络补全）、`updatePaper`（19 字段白名单，未知字段显式报错）、`setPaperCategories`（add/remove/replace，全量校验后写入，系统分类拒绝手动分配）、`manageCategory`（create/rename/move/delete，含环检测、系统分类保护、级联删除并解绑文献）、`deletePapers`（默认保留文件，`deleteFiles=true` 时数据库提交后删除库内文件）。
- 读取增强：`searchPapers` 新增 `categoryId` 过滤（非系统分类含全部后代；系统分类支持 all/recent/uncategorized/favorites 语义）；`getPaperDetails` 返回 `categoryIds`。
- `paperquaySyncFromZotero` 纳入同一护栏。

`bin/paperquay-mcp.cjs`：注册 6 个新工具（`import_pdfs`、`list_categories`、`manage_category`、`set_paper_categories`、`update_paper`、`delete_papers`），`search_papers` schema 增加 `categoryId`；`SERVER_VERSION` 对齐 package.json（0.1.40 → 0.1.48）。

文档：`docs/MCP_AGENT_INTEGRATION.md` 重写工具清单并新增「写入安全护栏」章节；`README.md` / `README_EN.md` 工具表更新为 15 个工具三大领域；`AGENTS.md` 项目地图同步。
