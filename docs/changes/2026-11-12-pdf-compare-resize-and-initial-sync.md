## 实测结果

使用现有英文原版及中文译版，各 47 页。从译版单栏直接点击对照后，两侧都成功绘制，可在同屏辨认英文原文和中文译文。加载阶段出现中文提示及未知页数；本轮首次观察到双栏可读的时间上界约为点击后 11.2 秒，包含工具调用间隔，不作为精确渲染耗时。

来源菜单显示“原版 PDF”和“译版 · 语言待确认”，两份文件的完整名称可通过悬停查看。左右滚动均能驱动另一侧翻页；关闭同步后可以独立滚动，重新开启后重新对齐。阅读页签失活再激活保留第 2 页，两侧仍可读。未复现 0.4.22 的左栏持续加载。

现有文库只读查询显示 29 个译版附件的 language 均为空。未为验收改写元数据，已知语言 `zh-CN` 的安装版 UI 分支记为未验证；语言和长名的逻辑回归仍保留。未在现有文库制造丢失文件或渲染失败，错误隔离和重试由受控组件测试覆盖。

## 缺陷与解决方案

| 缺陷 | 原因 | 修复与验证 |
| --- | --- | --- |
| 缩窄分栏后仍显示 Fit Width，但右侧文字被裁切；放大窗口后也未重新适配 | ResizeObserver 仅观察页面覆盖层；`PDFViewer.update()` 不重新计算适配比例 | 观察阅读容器，按动画帧合并 resize；仅在尺寸变化时重新应用适配预设，保留数字缩放。覆盖缩窄、放大和页签激活，断言文档任务保持一个。 |
| 从原版第 2 页进入对照后，同步已开启，右栏仍停第 1 页 | 页数和页 DOM 可以先于 `pagesinit` 就绪；原实现提前消耗同步 token，随后初始化恢复覆盖跳页 | 将页面初始化状态绑定到文档及重试 revision；同步等待 `pagesinit` 后再消费 token。测试复现“已知页数及页节点，但初始化尚未完成”，并检查初始化及后续绘制后仍在目标页。 |

两项新增回归在修复前分别因未观察容器和提前消费 token 失败；修复后通过。`npm run check` 类型检查、前端构建和全部 **976/976** 测试通过。受控回归使用实际组件 hooks 与替代 PDF.js/DOM；它不能替代新安装包的桌面验证。
