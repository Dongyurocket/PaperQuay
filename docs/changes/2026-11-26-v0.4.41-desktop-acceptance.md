## 4. FAIL 详情

### FAIL-01（P1）知识图谱工作区画布空白，并在切换/重启后崩溃到错误边界

**步骤**
1. 冷启动应用（隔离副本），默认落在「知识图谱」标签。
2. 观察侧栏：196 节点 · 845 关系；「主题总览 / 单论文网络 / 主分类」；文献 196、语义相似 617、文献互引 228 均勾选。
3. 点「刷新图谱」「重新布局」「适配视图」，等待 3–10s。
4. 展开「图谱统计」读取耗时；把渲染器从 Canvas 切到 WebGL 再切回。
5. 切到「我的文库」再切回「知识图谱」；再关闭应用重启后切到「知识图谱」。

**期望**：画布按布局绘制 196 个文献节点与 845 条关系；切换标签或重启后仍能正常显示。

**实际**
- 画布区域始终只有点阵背景，无任何节点、边、标签；窗口截图与**桌面级截图**（`A1-05-desktop.png`，真实屏幕像素）一致为空白。
- 数据链路正常：导出 JSON 含 196 节点/845 边；统计面板记录布局 fcose 1016ms、首帧 14ms；语义覆盖 169/196。
- Canvas 与 WebGL 两种渲染器都空白，排除单一渲染后端问题。
- 切换主题后（`A7-03-graph-dark.png`）与重启后切标签（`final-state.png`）出现错误边界：
  `Graph workspace failed to load — Cannot read properties of null (reading 'value')`，点「Reload workspace」可恢复侧栏，但画布仍空白。

**复现率**：画布空白 6/6（首次启动、刷新、重新布局、切换渲染器、切换主题、重启后）；错误边界崩溃 3/4 次进入该工作区（另 1 次仅空白未崩溃）。

**疑似模块**：`src/features/graph/*`（图谱快照→布局→渲染管线与工作区容器）；错误信息提示某处读取 `null.value`，常见于主题/配置对象或画布上下文在挂载前为空。

**建议修复**
1. 在图谱工作区加渲染前置断言与兜底：`canvas.getContext` 为空、快照为空、布局结果为空时给出显式状态而非静默空白。
2. 定位 `Cannot read properties of null (reading 'value')`：在主题切换、标签重挂载两条路径上抓栈；重点检查图表配置/主题对象取值时机。
3. 用 `PAPERQUAY_PERF=1` 复核首帧耗时为何记录 14ms 但无绘制（疑似画布尺寸为 0 或 draw 调用被跳过）。

**严重级别**：P1（图谱工作区整体不可用，无数据丢失）。

### FAIL-04（P2）筛选无结果时沿用「空库」空态文案

**步骤**：「我的文库」→ 筛选 → RAG 索引状态=待更新（或 已索引 + MinerU 已解析）→ 结果 0 条。

**OBS-01（P2 候选）MinerU 状态徽标与 RAG 来源不一致；「MinerU 已解析」筛选恒为 0**

## 6. 结论与建议

1. **不建议把 0.4.41 作为「图谱可用」的稳定版对外发布**。文献库、RAG 状态管理、阅读器、笔记四条主路径在实机上基本可用（A1/A2/A4/B2/B4/B7 通过），但知识图谱工作区在 196 篇规模下**既不渲染也不稳定**，属于该版本的核心功能缺口。
2. **建议发 0.4.42 修复 P1-01（图谱渲染 + 空值崩溃）与 P1-02（设置侧栏溢出）**；两项均为低风险改动，且 P1-02 同时解锁 B8/Embedding 的后续验收。
3. P2 两项（任务列表无响应、筛选空态文案）可随下一版一并处理；OBS-01 需在真实 profile 复核后再定性。
4. 数据安全：全程使用 `%TEMP%\pq-accept-0.4.41` 隔离副本，真实 `%APPDATA%\PaperQuay` 的 sqlite mtime 与内容未变，未生成 WAL/SHM；临时副本与截图保留供排查。
5. 仓库未改动：`git status` 仅有验收前既存的未跟踪文件（`docs/plans/2026-11-25-long-document-rag-and-overview.md`、`scripts/*`），本次仅新增本报告。
