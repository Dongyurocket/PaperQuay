# 译文缓存写入失败导致全文翻译任务被判失败

- 日期：2026-11-19
- 版本：0.4.34
- 范围：阅读器全文翻译、单块重译、文献库预览全文翻译共用的译文缓存写入链路

## 现象

全文翻译完成后，任务中心显示「1 个任务失败」，详情为：

> 翻译完成，已生成 892 段译文；译文缓存写入失败，本次结果仅保留在当前窗口

模型调用与译文生成均已完成，失败发生在把 `TranslationMap` 写入
`<mineruCacheDir>/document-<hash>/translations/<language>.json` 的最后一步。

2026-11-20 现场确认：首次失败后，用户于 00:26 重新点击一次全文翻译，
成功生成缓存文件（默认 AppData 缓存目录、约 185 KB / 892 条、未勾选只读）；
00:36 重启应用后中文正常，来自这次成功写入。也就是说，首次运行时**进度写入
和最终写入都没有落盘**（缓存文件直到重试成功才创建），但目标路径本身完全
可写；这是一次持续到本次任务结束的瞬时写入故障，不是只读、权限或自定义
目录问题。

## 根因

0.4.34 的写入链路是：

1. `writeTranslationCache` 只写入当前配置的 `mineruCacheDir`；
2. 主进程 `write_text_file` 先写临时文件，再 `rename` 覆盖目标；
3. `assertWriteAllowed` 只允许应用数据目录、文库存储目录、译版目录和已批准的缓存目录。

因此以下情况都会让缓存写入稳定或瞬时失败，而译文本身仍已生成：

- 旧 `assertWriteAllowed` 每次写缓存都会 `store.load()` 读取整个文库；
  当另一个进程（MCP 写入、备份、导入）短暂持有文库数据库时，缓存写入会
  在真正落盘前因 `SQLITE_BUSY` 等错误失败，即使目标目录完全可写。本案例
  首次运行时所有写入（含进度写入）都没有生成文件，重试后同一路径成功，
  与这一原因最吻合；
- 自定义 MinerU 缓存目录位于已断开的磁盘、不可写目录或权限受限位置；
- 目标 JSON 带只读属性（备份/恢复后常见，本次现场已排除）；
- Windows 上杀毒软件、云同步客户端或另一个进程短暂持有目标文件，导致
  `rename` 返回 `EPERM` / `EBUSY` / `EACCES`；
- 目标目录被删除或替换，`mkdir`/`rename` 失败；
- 重复点击全文翻译或缓存已完整时，应用仍尝试重写一份相同内容，撞上上述
  任一条件后误报任务失败。

旧实现没有重试、没有备用目录，并且只要缓存写入失败就把整个翻译任务标记为
`error`，于是出现「翻译完成但任务失败」。大文档（段数多）会触发更多次
「临时文件 + rename」，命中瞬时文件锁的概率更高。

## 修复

### 主进程写入

`electron/backend/fileCommands.cjs`：

- 应用数据目录和已批准的缓存目录先做无数据库的快速判断，不再为了写缓存去
  `store.load()`；文库临时繁忙或损坏时，译文缓存仍可写入；
- 对 `EPERM` / `EBUSY` / `EACCES` / `ENOTEMPTY` / `EMFILE` / `ENFILE`
  做 3 次短重试；
- 重试前清除目标文件只读属性（仅缓存文件路径）；
- 原子替换仍失败时退化为直接覆盖，保证缓存可用性优先；
- 最终错误信息带上路径和 `code`，便于定位。

### 渲染层缓存

`src/features/reader/readerTranslationCache.ts`：

- 写入失败时先读回现有缓存；如果缓存已经包含本次全部译文（例如文件只读、
  重复点击全文翻译、上一次进度写入已落盘），直接按成功处理，不再报错或重复
  写一份到备用目录；
- 主缓存目录写入失败且缓存不完整时，自动写入默认缓存目录
  （`appDefaultPaths.mineruCacheDir`，位于应用数据目录内）；同一篇文献后续
  写入直接使用已验证可写的备用目录；
- 读取时同时检查主缓存与默认缓存，按译文条数、再按 `translatedAt`
  选择更完整的一份，避免回退写入后读到旧的主缓存；
- 两个目录都失败时才抛出合并错误，UI 可同时看到两个路径的失败原因。

`src/features/reader/useDocumentTranslation.ts`：

- 进度写入或最终写入成功后清空之前的缓存错误，避免“前面某次写入失败、
  最终已成功”仍被误报为任务失败。

## 验证

- `npx tsc --noEmit` 通过。
- `npm test`：803 项，802 通过、1 跳过、0 失败。
- `npm run build` 通过（本机 esbuild 临时目录受限，构建时使用项目内 `TEMP`）。
- 新增测试：
  - `tests/readerTranslationCache.test.ts`：主目录失败回退、默认目录读取、
    双缓存取更完整者、已有完整缓存时重写失败按成功处理、双目录失败合并报错；
  - `tests/fileCommands.test.ts`：UTF-8 写入、只读目标文件可恢复写入、
    应用数据目录与已批准缓存目录在文库数据库不可用时仍可写入。

## 后续

若线上仍出现「两个目录都失败」，新错误信息会包含两个路径及系统错误码，
可直接区分权限、磁盘、路径和文件锁问题。
