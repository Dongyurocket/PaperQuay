# 2026-11-12 - PDF 对照加载与来源状态

## 现象

从译版直接进入 PDF 对照时，原版加载可能随父组件更新反复重启。两栏页数、错误和文件名可能沿用活动译版状态，加载期间显示的 1/1 也不能证明文档已就绪。

## 根因

原版来源描述对象随渲染重新创建，触发 PDF 初始化依赖变化；父层状态未完全绑定实际左侧来源。远处同步目标没有加入待挂载页集合，导致同步等待无法推进；内存 PDF 的空路径入口被误判为空文档。

## 修改

- 按原版路径独立 memo 来源；页数及错误快照绑定文档来源、数据身份和重试 revision。
- 两栏按实际来源传递文件名、计数、错误、滚动和阅读热图；原版不可用时明确展示，缺译版时保留附加引导。
- 区分文档加载、文档就绪、页面绘制和失败；未知页数不再显示 1/1，错误带文件名及人工重试。
- 保留任务取消和迟到文档释放；支持内存 PDF，并让远处同步页节点可挂载。同步页按各文档真实页数截断，以 token 确认防止回传循环。
- 应用版本递增为 0.4.23，沿用标签触发的 Windows x64、Linux x64、macOS x64 发布流程。

## 验证

- 生命周期回归连接真实 ReadingStage、TranslatedPdfPane 及两侧 PdfViewer hooks，使用受控 PDF.js/DOM 夹具；覆盖重复渲染、换源、取消、迟到结果、来源归属、独立失败、重试，以及 47/3 页双向同步。
- 来源标签及初始化回归覆盖已知/未知语言、长文件名及远程初始化参数。
- 版本递增为 0.4.23 后，`npm run check` 类型检查、前端构建及全部 973 项测试通过。
- 中间同版本诊断包在隔离 profile 和 `--no-sandbox` 条件下显示了英文原版、中文译版及各自 47 页；此结果不能证明最终发布包的常规启动与桌面验收通过。产品启动配置未因此更改。
- 最终本地解包包正常启动退出 `0x80000003`，Windows Shell 路径曾出现 SmartScreen；用户反馈隔离快捷方式无窗口。替换临时目录、使用新 profile 仍退出，同版本开发 Electron 的 `--version` 也退出，精确原因未确定。
- 用户授权先提交、推送和发布，更新本机安装版后再继续桌面验证及问题迭代。最终安装版桌面验收仍待完成。

本次修改不增加既有文献、PDF、附件、用户数据库或缓存的迁移、改写、复制或删除。诊断只使用新建隔离 profile 引用已有 PDF 路径；已安装版 MCP 后台服务保持运行。
