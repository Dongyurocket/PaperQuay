# PaperQuay 笔记宪章（Notes Charter）

> 本文件是 PaperQuay 笔记系统的"宪法"：规定页面类型、命名与链接规范、摘录卡的证据红线。
> 内置 Agent、外部 agent（经 MCP）、人类用户共同遵守。修改本文件需要明确理由并同步更新模板。

## 0. 三条根本原则

1. **Tiptap JSON 是唯一事实源**。正文以 `notes.content_json` 存储；Markdown / HTML 是导出与同步格式，不是存储格式。
2. **锚点 ID 不可丢**。任何指向文献位置（页码、blockId、pdfLocation）的锚点，在编辑、AI 改写、Markdown 往返中都必须保真。
3. **提炼可以自由，证据必须保真**。AI 和人类可以任意改写提炼性文字，但来源锚点和原文快照一个字都不能动。

## 1. 页面类型（Page Types）

每篇笔记属于且仅属于一种页面类型。类型决定模板与最低内容要求，不决定文件夹归属。

页面类型已通过 `notes.page_kind` 入库。旧 `notes.type` 保留为来源语义（`highlight`、`area`、`standalone`、`ai-chat`），`page_kind` 是结构语义（下表 8 值），两者不可互相替代；历史笔记可暂为 `null`。模板、检索过滤、内置 Agent 与 MCP 白名单均以 `page_kind` 校验结构类型。

| 类型 | 标识 | 用途 | 最低要求 |
|------|------|------|----------|
| 论文卡片 | `paper-card` | 一篇文献的结构化档案：问题、方法、实验、我的判断 | 必须挂 paperId；必须含「我的判断」 |
| 概念页 | `concept` | 一个概念/方法/术语的定义与理解 | 必须有定义段；尽量挂来源锚点 |
| 综述页 | `synthesis` | 跨多篇文献的比较、归纳、研究脉络 | 至少引用 2 篇文献（paper-reference） |
| 问答页 | `qa` | 一个具体问题及其回答与证据 | 必须有「证据位置」段 |
| 摘录卡 | `excerpt` | 对一段原文的提炼式摘录 | 必须有来源锚点；见 §3 红线 |
| 索引页 | `index` | 一个主题/项目的入口与目录 | 主要由 [[双链]] 组成，少写正文 |
| 日志页 | `log` | 按时间推进的研究日志 | 条目倒序（最新在上），每条带日期 |
| 总览页 | `overview` | 全局学习/研究状态的总览 | 每周手工或 agent 刷新一次 |

## 2. 命名与链接规范

- **标题是 Markdown 快照，不是唯一键**：Tiptap 的 `wikiLink` 节点同时保存目标 `noteId` 与标题快照。关系解析、`note_links` 写入和显示/导出均优先按 `noteId` 查找当前标题，因此目标笔记改名后无需全库改写引用方笔记，存量关系仍保持有效。
- **残留风险**：纯 Markdown 中手写的 `[[旧标题]]` 没有持久化 `noteId`，仍只能按标题解析，目标改名后可能失配或产生歧义；vault 导出会将已有 ID 的双链写成当前标题，回导时再恢复 ID。
- **概念页用术语命名**：如「KV Cache」「FlashAttention」，不加「笔记」「总结」等后缀。
- **论文卡片用「年份-第一作者-短题」**：如「2023 Vaswani Attention Is All You Need」。
- **标签是横切维度，文件夹是归属维度**：一篇笔记只在一个文件夹，但可有多个 `#标签`。项目/领域用文件夹，主题/方法用标签。
- **索引页链接而非复制**：索引页只放 `[[双链]]` 和一句话说明，不粘贴正文。

## 3. 摘录卡红线（Excerpt Contract）

摘录卡是「提炼式摘录」：正文是 AI 或用户对原文的提炼改写，**不是逐字复制**。

1. **来源锚点保真**：`anchors[]`（paperId、pageIndex/blockId/pdfLocation、label）由系统写入，禁止人工或 AI 编辑。
2. **原文快照保真**：如带原文快照（excerpt 字段），视为证据，禁止改写。
3. **提炼正文自由**：正文可以随意重写、重排版、重识别（入库后），这是摘录卡存在的意义。
4. **禁止无中生有**：提炼不得引入原文没有的主张；拿不准的推断要标注为「我的推断」。

## 4. Agent 行为准则

- 内置 Agent 增删改笔记一律走 `write_notes` 工具并生成审批卡，由用户确认后落库。
- 外部 agent 经 MCP 写入时遵守同一套校验（标题/正文非空、类型白名单、标签上限 30）。
- Agent 新建页面时优先使用对应页面类型的模板（见编辑器 `/` 菜单）。
- Agent 不得修改锚点与原文快照；不得把摘录卡的「提炼正文」当作原文引用回文献。

## 5. 与 Obsidian 的边界

Markdown vault 双向同步已落地（v0.2.0；对应计划 `docs/plans/2026-09-24-notes-system-painpoints-and-solutions.md` 的 P1-3，同步由笔记工作区手动触发）：

- 每篇笔记对应一个 `.md` 文件，frontmatter 携带 `id`、`type`、`paperId`、`folder`、`tags`、`sources[]`、`anchors[]`、`createdAt`、`updatedAt`。
- `id` 是同步锚，禁止在 Obsidian 侧修改；新增文件没有 `id` 时，导入时按新笔记处理。
- 富文本元素在 Markdown 中以占位语法表示：锚点芯片为 `paperquay://anchor/<id>` 链接，文献引用为 `[n]` + 文末 GB/T 7714 列表，`[[双链]]` 与 `#标签` 原样保留。共享 Markdown→Tiptap 解析器已在 vault 回导、MCP 笔记写入和编辑器缺失 `content_json` 兜底中启用：标题、列表、基础内联格式、代码块、引用块、双链和标签可重建；只有 frontmatter/本地文库已知的锚点 ID 与 paperId 才恢复为专用节点，未知值保留为普通文本。
